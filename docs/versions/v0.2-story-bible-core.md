# v0.2 Story Bible Core

## 目标

加入最小可用故事圣经：人物、地点和规则。它应该像本地 Obsidian 风格的故事 wiki，而不是插件私有数据库。

## 实现

- Story Bible 作为独立 capability 挂载，不和 Manuscript 耦合。
- 文件结构：

```text
lore/
  characters/
  locations/
  rules/
```

- `StoryElement` 使用 Markdown + YAML frontmatter。
- 通用字段：
  - `id`
  - `type`
  - `name`
  - `aliases`
  - `tags`
  - `summary`
  - `visibility`
  - `createdAt`
  - `updatedAt`
- 类型模板：
  - character：角色定位、目标、冲突、说话方式、当前状态
  - location：区域、氛围、规则、当前状态
  - rule：分类、重要性、规则陈述、例外
- Story Bible 树按类型分组。
- 命令：
  - 新建人物
  - 新建地点
  - 新建规则
  - 打开故事元素
  - 重命名故事元素
  - 删除故事元素
  - 搜索故事圣经
  - 从选中文本创建故事元素

## 优化

- 使用结构化 parser 或带测试的小型专用 parser 解析 frontmatter。
- 缓存故事元素元数据，加快树渲染。
- 正文 Markdown 不做限制。
- 模板设计要方便后续替换。

## 打磨

- 卡片模板短而有用。
- QuickPick 搜索支持别名和标签。
- 从选中文本创建时预填名称和摘要。
- 重名或重复别名给出警告。

## 验收标准

- 作者可以创建并浏览人物、地点和规则。
- 故事圣经文件保持人可读的 Markdown。
- 损坏 frontmatter 会显示警告，但不会拖垮整棵树。
- 测试覆盖模板创建、解析、搜索、重命名和重复检测。

## 风险

- 基础模型还没验证就加入太多资料类型。
- 太早把卡片做成刚性表单。
- 把重要信息藏进 JSON-only 字段。
