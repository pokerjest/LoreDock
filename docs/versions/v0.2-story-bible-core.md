# v0.2 Story Bible Core

## 目标

加入最小可用故事圣经：人物、地点和规则。它应该像本地 Obsidian 风格的故事 wiki，而不是插件私有数据库。

v0.2 的核心目标不是把世界观系统一次做满，而是验证 LoreDock 的第二个业务 capability：普通 Markdown 文件作为 canon，结构化 frontmatter 作为可验证元数据，后续大纲、场景卡、知识图谱和一致性检查都能通过稳定 ID 引用这些 Card。

## 产品参考与边界

- 吸收 Obsidian 的本地 Markdown、frontmatter properties、aliases、tags 和快速搜索思路；但 v0.2 不做反链、未链接提及、图谱和全文索引，这些属于 v0.5 Knowledge Graph。
- 吸收 World Anvil 和 Campfire 的模板提示语：人物、地点和规则文件应该给作者短而有用的填写提示；但 v0.2 不做关系网、地图、时间线、秘密权限、百科发布或大型世界构建门户。
- 吸收 Novelcrafter Codex 和 Plottr Story Bible 的故事资料组织思路：资料条目要能被场景卡、大纲和后续 AI 上下文稳定引用；但 v0.2 不做场景卡、剧情矩阵、AI 上下文拼装或写作建议。
- 保持 v0.0-v0.2 地基期边界：少做资料类型，先把文件格式、ID、校验、搜索、树视图和 capability 协作跑通。

## 实现

- Story Bible 作为独立 capability 挂载，不依赖 Manuscript 私有存储；需要章节信息时只能可选依赖 Manuscript 暴露的公开 `ManuscriptReader`。
- Story Bible capability ID 固定为 `story-bible.core`。
- Story Bible Card schema ID 固定为 `story-bible.element`，关键词定义 schema ID 固定为 `story-bible.tag`，当前 schema version 均为 `0.2.0`。
- Story Bible 通过 v0.0 `SchemaRegistry` 注册 `story-bible.element` 和 `story-bible.tag` 的 `0.2.0` schema 元数据；实际 frontmatter validation 由 Story Bible 模块 validator 执行，未知或未来 `schemaVersion` 进入 diagnostics，不自动迁移。
- Card frontmatter 不单独保存 `schema` 字段；`story-bible.element` 由所在目录和 `type` 推断，并用于 `SchemaRegistry` 与 validator。Keyword 定义必须显式保存 `schema: "story-bible.tag"`，因为 `lore/tags/` 是定义目录，不是 CardType 目录。
- 新增 `loredock.enableStoryBible` 命令，通过 preview、confirm、apply 将 `story-bible.core` 写入 `.loredock/project.json`，并创建 v0.2 所需的最小目录结构。
- `loredock.enableStoryBible` 只在 `.loredock/project.json` 可解析且 validation 通过时执行；manifest 缺失时提示先运行 `loredock.initProject`，manifest degraded 时提示先修复项目清单。
- `loredock.enableStoryBible` 写入 `.loredock/project.json` 时必须更新项目 manifest 的 `updatedAt`；用户取消 preview 时不能写入 capability、目录或文件。
- `loredock.enableStoryBible` apply 时先创建 `lore/` 最小目录结构，最后写入 `.loredock/project.json`；如果目录创建失败，不能写入 `story-bible.core` capability。
- 如果最后写入 `.loredock/project.json` 失败，但 `lore/` 目录结构已经创建成功，不能静默删除这些目录；必须报告“部分启用” diagnostics，并让下一次 `loredock.enableStoryBible` 走“`lore/` 已存在但 capability 未启用”的恢复路径。
- `loredock.enableStoryBible` apply 后必须重新读取并验证 `.loredock/project.json` 和 Story Bible 目录结构，失败时报告 diagnostics。
- 重复运行 `loredock.enableStoryBible` 必须保守处理：不能重复写入 capability ID，不能覆盖现有 `lore/` 文件；已有 Story Bible 时只刷新/打开 Story Bible 树或报告现有状态。
- 如果 `lore/` 已存在但 `.loredock/project.json` 尚未启用 `story-bible.core`，`loredock.enableStoryBible` 必须先扫描并验证现有 Story Bible 文件；没有 error 时只写入 capability ID，存在 error 时只报告 diagnostics。
- `.loredock/project.json` 仍保持薄 manifest，只记录项目身份、版本和启用 capability；不能把人物、地点、规则列表塞进项目 manifest。
- v0.2 不引入 `lore/manifest.json` 作为 canon。每个 Card Markdown 文件本身就是 canon；缓存只能是内存缓存，后续索引文件留到 v0.5。
- 文件结构：

```text
lore/
  characters/
  locations/
  rules/
  tags/
```

- 只支持三类内置 Card：
  - `character`
  - `location`
  - `rule`
- v0.2 UI 和公共接口把人物、地点、规则统一视为 `Card`。Card 是可被浏览、搜索、挂关键词、被后续模块引用的故事对象；v0.2 不新增 `cards/` 目录，三类卡牌仍分别保存在 `lore/characters/`、`lore/locations/`、`lore/rules/`。
- `CardType` 是稳定类型 ID。v0.2 只内置注册 `character`、`location`、`rule` 三个静态 CardType；动态 CardType schema registry 留到 v0.6 World Modules。
- `lore/tags/` 只存放用户主动定义的关键词定义，不是第四类 CardType；关键词定义不能出现在 Story Bible 人物、地点、规则树的 Card 分组中。
- v0.2 不创建 `factions/`、`items/`、`events/`、`timelines/`、`maps/` 或 `relationships/`；这些属于 v0.6/v0.7 或更后续版本。
- `StoryElement` 是 v0.2 的 Card 持久化形态，使用 Markdown + YAML frontmatter。frontmatter 是结构化元数据，正文 Markdown 是作者自由书写区。
- 通用 frontmatter 字段：
  - `schemaVersion: "0.2.0"`
  - `id`
  - `type`
  - `name`
  - `aliases`
  - `tags`
  - `summary`
  - `visibility`
  - `status`
  - `createdAt`
  - `updatedAt`
  - 可选 `chapterRefs`
- `id` 必须项目内唯一，由统一 ID utility 生成；生成后不随名称、文件名或目录变化而改变。
- `type` 必须与所在目录一致：`lore/characters/` 下只能是 `character`，`lore/locations/` 下只能是 `location`，`lore/rules/` 下只能是 `rule`。
- `name` 必须是非空字符串；显示名以 `name` 为准，不以文件名为准。
- `aliases` 必须是字符串数组；读取时 trim，空值进入 diagnostics，重复值进入 warning。
- `tags` 必须是字符串数组，保存 keyword slug，不保存 UI 显示名；读取时 trim，空值进入 diagnostics，重复值进入 warning。
- `summary` 是短摘要，必须是字符串，可以为空字符串。
- `visibility` 当前支持：
  - `public`：普通公开设定。
  - `spoiler`：含剧透或后期信息。
  - `private`：作者私有备注。
- `visibility` 在 v0.2 只用于树视图和搜索筛选，不做发布权限、读者权限或 AI 权限控制。
- `status` 当前支持：
  - `draft`
  - `canon`
  - `archived`
- `createdAt` 和 `updatedAt` 必须是 ISO 时间戳字符串。
- `chapterRefs` 是可选数组，只允许保存 v0.1 的稳定 `chapterId`；它不是反链，不扫描正文，不从正文自动生成。
- 如果 Manuscript capability 未启用，`chapterRefs` 只做数组和字符串格式校验；如果 Manuscript capability 已启用，必须通过 `ManuscriptReader` 校验引用的章节是否存在。
- 未知 frontmatter 字段必须保留，不进入 error；Story Bible 元数据编辑只能改写 v0.2 已知字段，避免破坏未来 CardType、模板包或用户手写扩展字段。
- Card 文件名不是身份。新建时可根据 `name` 生成稳定 ASCII slug，并在冲突时追加单调序号；重命名 Card 默认只更新 frontmatter 的 `name`、`tags` 和 `updatedAt`，其中新对象主关键词写入 `tags[0]`，旧对象关键词保留在后续位置；不自动移动文件，避免破坏用户手写 Markdown 链接。
- 删除 Card 必须沿用 v0.1 的 preview、confirm、apply 和回收站语义：先移入回收站，不直接永久删除用户资料。
- Story Bible 使用资源垃圾桶，不使用 v0.1 的手稿垃圾桶；资源垃圾桶路径固定为 `.loredock/trash/resources/story-bible/<trash-id>/`，不能写入 `.loredock/trash/manuscript/`。
- 每个资源垃圾桶条目目录固定包含 `trash-item.json`，用于保存原始相对路径、资源类型、CardType（仅 Card 需要）、标题、删除时间、原始文件名和还原所需元数据；资源类型当前只允许 `card` 或 `keyword-definition`，这些垃圾桶元数据只用于恢复，不是 Story Bible canon。
- 删除 Card 或普通 Keyword 定义时，将对应 Markdown 移入资源垃圾桶；还原时移回原路径并重新进入 Story Bible 树或 Keyword Catalog；永久删除时只允许递归删除对应 `.loredock/trash/resources/story-bible/<trash-id>/` 目录。
- 资源垃圾桶视图通过扫描 `.loredock/trash/resources/story-bible/*/trash-item.json` 构建，不引入 `lore/manifest.json` 或单独的资源垃圾桶索引。
- 还原资源垃圾桶项目时，如果原始目标路径已经存在，必须拒绝覆盖并报告 diagnostics；不能自动改名还原。
- 永久删除资源垃圾桶项目必须在 preview/apply 之外再做一次危险删除确认；用户取消确认时不能删除文件或改写垃圾桶元数据。
- 类型模板要短而有用：
  - character：角色定位、目标、冲突、说话方式、当前状态。
  - location：区域、氛围、重要规则、当前状态。
  - rule：分类、重要性、规则陈述、例外。
- 模板正文只能提供 Markdown 提示，不要把长篇内容塞进 frontmatter。
- Story Bible 树按类型分组：人物、地点、规则。
- 单 workspace 直接显示 Story Bible 内容；多 workspace 时先按 workspace 分组，树节点和命令参数都携带目标 workspace，避免写入错误 folder。
- 树中的 Card 节点必须能打开对应 Markdown 文件。
- Story Bible 树要能显示 degraded 文件：单个文件 frontmatter 损坏时显示 warning 节点或降级节点，但不能拖垮整棵树。
- 命令：
  - 启用 Story Bible
  - 新建人物
  - 新建地点
  - 新建规则
  - 打开 Card
  - 重命名 Card
  - 编辑 Card 元数据
  - 删除 Card
  - 切换 Story Bible 资源垃圾桶视图
  - 还原资源垃圾桶项目
  - 永久删除资源垃圾桶项目
  - 浏览 Story Bible 关键词
  - 定义 Story Bible 关键词
  - 编辑 Story Bible 关键词定义
  - 删除 Story Bible 关键词定义
  - 搜索故事圣经
  - 从选中文本创建 Card
  - 刷新 Story Bible 树

## 卡牌与关键词系统

- v0.2 必须把 `tags` 作为 Story Bible 的一等 `Keyword` 系统，而不只是自由文本字段。Keyword 类似卡牌关键词：短、可见、可提示，用于给 Card 表达能力、主题、阵营、状态或规则钩子。
- v0.2 的卡牌系统边界只到“人物、地点、规则三类 Card 的卡片化展示并挂载 Keyword”；不做卡组、抽取、战斗、数值联动、效果执行或卡牌玩法。
- frontmatter 字段继续叫 `tags`，保持 Markdown 和 Obsidian 兼容；UI 文案使用“关键词”。
- `tags` 的持久化值必须是 keyword slug，界面显示时再映射为面向作者的 label；Card frontmatter 中不保存关键词说明、颜色或长文本。
- keyword slug 统一使用小写 ASCII 字母、数字、`-` 和 `/`；普通关键词可以使用 `theme/revenge`、`relationship/rival` 或 `magic` 这类 slug。
- keyword slug 必须由非空 path segment 组成；每个 segment 只能包含小写 ASCII 字母、数字和 `-`，不能以 `-` 开头或结尾，不能包含空 segment、`.`、`..`、反斜杠、空格或 URL 编码字符。
- 普通关键词是可共享关键词，允许多个 Card 使用同一个普通 keyword slug；共享只影响 Keyword Catalog 的使用次数，不进入 warning。
- `character/`、`location/` 和 `rule/` 前缀保留给对象主关键词和历史对象关键词；用户手动创建普通关键词时不能使用这些保留前缀。
- 用户可以主动定义普通关键词。关键词定义使用 Markdown + YAML frontmatter，保存在 `lore/tags/<slug>.md`；如果 slug 包含 `/`，路径按目录展开，例如 `theme/revenge` 保存为 `lore/tags/theme/revenge.md`。
- 关键词定义 frontmatter 字段：
  - `schemaVersion: "0.2.0"`
  - `schema: "story-bible.tag"`
  - `slug`
  - `label`
  - `description`
  - `category`
  - `appliesTo`
  - `createdAt`
  - `updatedAt`
- `label` 是用户看到的关键词名；`description` 是 tooltip 或帮助文本；正文 Markdown 可写更长解释和使用约定。
- `category` 使用 keyword category slug，不封死枚举；内置建议值包括 `theme`、`role`、`state`、`mechanic`、`relationship`、`custom`。v0.2 只用于分组和显示，不驱动后续能力。
- `appliesTo` 是字符串数组，取值为 `any` 或 CardType ID；v0.2 识别 `character`、`location`、`rule`，遇到未知未来 CardType 只进入 warning，不阻塞读取。
- Story Bible 维护一个可重建的全局 Keyword Catalog；Catalog 从 `lore/tags/**/*.md` 的关键词定义和所有 Card frontmatter 的 `tags` 合并重建，不能引入单独 keyword 数据库或 tag manifest。
- Keyword Catalog 至少返回：
  - keyword slug。
  - display label。
  - description。
  - category。
  - appliesTo。
  - 使用次数。
  - 定义文件相对路径。
  - source status：`system-object`、`user-defined` 或 `inferred`。
- Keyword Catalog 的 source status 判定：
  - `system-object`：由人物、地点或规则 Card 的对象关键词生成，包括当前主关键词和保留的历史对象关键词。
  - `user-defined`：来自 `lore/tags/**/*.md` 中有效的普通关键词定义。
  - `inferred`：被 Card `tags` 使用，但没有有效关键词定义，也不是有效对象关键词。
- 有效但暂未被任何 Card 使用的普通关键词定义仍必须出现在 Keyword Catalog 中，使用次数为 `0`，便于作者先设计关键词体系再挂载到 Card。
- Keyword Catalog 提供全局关键词列表、使用次数、按输入前缀或模糊匹配的 QuickPick 提示、按 category 分组，以及按关键词筛选 Card。
- v0.2 Keyword 只服务 Story Bible UI 显示、QuickPick 提示、搜索、筛选和 Card 关键词展示；不自动改写 Markdown 正文，不扫描 Manuscript，不生成提及、反链或未链接提及。
- 每个新建人物、地点和规则 Card 都必须自动生成一个对象主关键词，并写入该 Card 的 `tags`。
- 对象主关键词的存储格式为 `<type>/<slug>`，例如 `character/wu-jin`、`location/black-tower`、`rule/blood-magic`。
- `tags` 数组顺序有语义：`tags[0]` 必须是当前对象主关键词；历史对象关键词和普通关键词只能出现在后续位置。
- 对象主关键词的 display label 使用 Card 当前 `name`，例如存储为 `character/wu-jin` 时，界面显示 `吴烬`。
- 用户定义关键词的 display label 来自关键词定义的 `label`；未定义普通关键词和历史对象关键词默认用 slug 派生显示名，派生规则为去掉对象保留前缀后把 `-` 显示为空格。
- 对象主关键词 slug 生成必须确定、可重复；中文名称可通过统一 slug utility 转写，无法转写时使用同类型下确定 fallback。
- 对象主关键词 slug 与现有 keyword slug 冲突时追加单调序号，例如 `character/wu-jin-2`；不能覆盖其他 Card 已有关键词。
- 重命名 Card 时，根据新 `name` 生成新的对象主关键词并写入 `tags[0]`，旧对象关键词保留在后续位置，形成新旧并存。
- 如果重命名生成的对象关键词已经存在于该 Card 的历史对象关键词中，必须复用该 slug 并移动到 `tags[0]`，不能在同一 Card 内生成重复 keyword slug。
- 当前 `tags[0]` 对象关键词是该 Card 的主关键词，并以当前 `name` 显示；旧对象关键词继续用于搜索、筛选和提示，但不再作为主关键词显示。
- 编辑 Card 元数据时，用户可以编辑普通 keywords，也可以移除旧对象关键词；但不能删除或移动当前对象主关键词。
- 用户删除或损坏某个关键词定义时，不自动从 Card `tags` 中移除该 slug；Keyword Catalog 必须把它降级为 `inferred` keyword。
- 删除普通关键词定义必须将 `lore/tags/<slug>.md` 对应文件移入 Story Bible 资源垃圾桶，不能直接永久删除，也不能改写任何 Card frontmatter；如果该 slug 仍被 Card 使用，Keyword Catalog 继续以 `inferred` 返回。
- 关键词去重以 keyword slug 为准；display label 只用于显示和搜索，不作为持久化身份。

## 搜索规则

- `打开 Story Bible 卡牌库` 使用轻量 Webview，以卡牌画廊方式展示人物、地点和规则；信息结构可以参考 Steam 游戏库/商店页的分类、封面卡、状态标签和摘要布局，但视觉风格必须跟随 VS Code 编辑器主题，不使用独立的 Steam 蓝黑色调，也不引入远程图片或在线资源。
- 卡牌库的关键词 chip 和顶部统计 chip 必须使用低对比、透明或细边框样式；默认不能使用高饱和 `badge` 填充色，避免在不同 VS Code 主题下显得像外部网页按钮。
- 卡牌库需要提供类似游戏库的分类导航：左侧显示“全部卡牌、人物、地点、规则”和常用关键词分类/筛选，中间内容区按分类分组展示卡牌。
- 卡牌库 Webview 只服务 v0.2 的浏览、搜索、筛选和元数据编辑；Markdown 文件仍是 canon，Webview 不能引入单独数据库或隐藏状态。
- 点击卡牌时必须打开卡牌详情弹窗/模态面板，在弹窗内编辑 `name`、`aliases`、普通 keywords、`summary`、`visibility`、`status` 和 `chapterRefs`；用户不应被要求直接在 frontmatter 顶部手写这些元数据。
- 卡牌详情弹窗的填写区域必须按信息类别分组，例如“基础资料、关键词、状态、引用”，避免所有字段堆在一个扁平表单里。
- 对象主关键词在详情弹窗中分左右两侧显示：左侧显示面向作者的 `类型/名字`，例如 `人物/叶俊杰`；右侧以灰色等弱化样式显示持久化 keyword slug / id，例如 `character/u-08c11eff`。
- 普通/历史关键词输入建议不能依赖浏览器原生 `datalist` 的默认渲染；建议项必须自绘为左侧 `类型/名字` 或 `分类/关键词名`，右侧弱化显示持久化 keyword slug / id。
- 普通/历史关键词编辑必须使用“已选关键词 chip + 加号按钮”的标准交互；点击 `+` 打开关键词下拉选择，选中后加入 chip，chip 默认显示该 slug/id 对应的 display label，鼠标悬停时显示持久化 slug/id。
- 弹窗保存仍必须调用 `StoryBibleActions` 并走 preview、confirm、apply；取消弹窗不能改写文件。
- TreeView 仍保留为轻量导航和 degraded/垃圾桶入口；TreeView 中点击 Card 默认打开卡牌库并定位到该 Card，而不是直接要求用户编辑 frontmatter。
- 搜索范围至少包括：
  - `name`
  - `aliases`
  - `tags`
  - `summary`
  - 文件正文中的一级标题
- 搜索结果必须显示类型、名称和相对路径。
- 搜索必须同时匹配 keyword slug、keyword label 和 keyword description。
- 搜索支持按 `type`、`visibility`、`status` 和 keyword 过滤；v0.2 可以先通过 QuickPick 分组选项或命令参数实现，不需要复杂查询语法。
- 搜索只读 Story Bible 文件，不扫描 Manuscript 正文，不生成未链接提及。

## 从选中文本创建

- 从当前 editor 选中文本创建 Card 时，必须先让用户选择类型：人物、地点或规则。
- 选中文本预填 `name`；如果选中文本过长，只取第一行或合理截断作为名称，并把原选中文本放入 `summary` 或正文草稿。
- 创建前必须展示 preview，列出将创建的目录、文件和初始 frontmatter。
- 如果当前 workspace 尚未启用 Story Bible，提示先运行 `loredock.enableStoryBible`。
- v0.2 不自动把选中文本替换成链接，不自动改写 Manuscript 正文。

## 时间戳规则

- 启用 Story Bible 会更新 `.loredock/project.json` 的 `updatedAt`。
- 新建 Card 写入 `createdAt` 和 `updatedAt`。
- 重命名 Card、生成新对象主关键词、更新别名、关键词、摘要、visibility、status 或 chapterRefs 时更新该 Card 的 `updatedAt`。
- 用户直接编辑 Markdown 正文时不强制改写 frontmatter 的 `updatedAt`，避免普通写作产生元数据 churn。

  - 列出资源垃圾桶条目，并返回垃圾桶 ID、资源类型、可选 CardType、标题、删除时间、原始相对路径和垃圾桶相对路径。
  - `listKeywords()`：列出 Keyword Catalog，并返回 slug、label、description、category、appliesTo、使用次数、定义文件相对路径和 source status。

  - 按 ID 读取 Card DTO。

  - `searchKeywords()`：按文本搜索 Keyword 的 slug、label、description 和 category，供 QuickPick 提示使用。
  - 读取 Card 正文。

- v0.2 必须通过 service registry 暴露受控 `StoryBibleActions`：

  - 删除 Card。

  - 永久删除资源垃圾桶项目。

## Story Bible 诊断

- 以下情况必须进入 diagnostics：
  - `lore/` 路径不安全或通过 symlink 解析到 workspace 外。
  - Card 文件 frontmatter 缺失或损坏。
  - `schemaVersion` 缺失或不是 `"0.2.0"`。
  - `id` 缺失、为空或重复。
  - `type` 缺失、未知或与所在目录不一致。
  - `name` 缺失或为空。
  - `aliases`、`tags` 或 `chapterRefs` 不是数组。
  - `aliases`、`tags` 或 `chapterRefs` 包含空字符串。
  - `tags` 包含非法 slug。
  - 普通关键词使用了 `character/`、`location/` 或 `rule/` 保留前缀。
  - 当前 Card 缺少当前类型的对象主关键词，或 `tags[0]` 不是当前对象主关键词。
  - 同一 Card 内出现重复 keyword slug。
  - 同一对象主关键词 slug 被多个 Card 使用。
  - Keyword 定义文件 frontmatter 缺失或损坏。
  - Keyword 定义 `schemaVersion` 缺失或不是 `"0.2.0"`。
  - Keyword 定义 `schema` 不是 `"story-bible.tag"`。
  - Keyword 定义 `slug` 非法、为空、使用对象保留前缀，或与 `lore/tags/<slug>.md` 路径不一致。
  - Keyword 定义 `label` 为空。
  - Keyword 定义 `category` 缺失、为空或不是合法 slug。
  - Keyword 定义 `appliesTo` 不是数组。
  - Keyword 定义 `appliesTo` 包含 v0.2 未知 CardType ID 时进入 warning，但不阻塞读取。
  - 同一个普通 keyword slug 出现多个 Keyword 定义文件。
  - `visibility` 不是 `public`、`spoiler` 或 `private`。
  - `status` 不是 `draft`、`canon` 或 `archived`。
  - `createdAt` 或 `updatedAt` 不是 ISO 时间戳字符串。
  - Markdown 文件位于 `lore/` 下但不在 `characters/`、`locations/`、`rules/` 或 `tags/` 中。
  - Markdown 文件位于 `lore/tags/` 下但不是有效关键词定义。
  - 资源垃圾桶路径不是 `.loredock/trash/resources/story-bible/` 下的 workspace-relative path，或通过 symlink 解析到 workspace 外。
  - 资源垃圾桶条目元数据缺失、损坏、资源类型未知或缺少原始相对路径。
  - `chapterRefs` 引用不存在的章节。
  - 同类型下出现重复 `name` 或重复别名。
- 单个 Card 损坏时，Story Bible 树进入局部 degraded：损坏文件显示 diagnostics，但其他有效文件仍可浏览和打开。
- Story Bible 全局路径不安全时，禁用所有写入命令，只允许显示 diagnostics。
- v0.2 不自动修复损坏 frontmatter，不自动删除 orphan 文件，不自动重写用户正文。

## 优化

- 使用结构化 parser 或带测试的小型专用 parser 解析 frontmatter；不能用脆弱的临时字符串切割处理核心字段。
- 缓存 Card 元数据，加快树渲染；缓存必须可由文件系统重新构建，不能成为唯一真相。
- 文件 watcher 只在 `lore/**` 相关文件变化时刷新 Story Bible 树和缓存。
- 正文 Markdown 不做限制。
- 模板设计要方便后续替换；v0.6 World Modules 和 v1.5 Template Packs 可以扩展字段和模板，但 v0.2 不提前实现动态 schema 编辑器。
- 别名匹配要考虑中文名称，不依赖英文 word boundary。

## 打磨

- 默认模板短而有用，避免表单感太重。
- Webview 卡牌库和 QuickPick 搜索支持别名、关键词、关键词提示和类型。
- 树视图、Webview 卡牌库、QuickPick 和元数据编辑入口要显示对象主关键词；普通关键词可以作为次要信息显示。
- Keyword 定义 QuickPick 要像卡牌关键词提示一样显示 label、category、description 和使用次数。
- 从选中文本创建时预填名称和摘要。
- 重名或重复别名给出 warning，不阻止创建，除非 ID 冲突或路径冲突。
- 编辑 Card 元数据必须优先使用卡牌库弹窗表单；QuickPick/InputBox 只作为命令面板或 Webview 不可用时的降级路径。
- 树视图要有清楚的空状态：尚未初始化项目、尚未启用 Story Bible、暂无人物、暂无地点、暂无规则。
- 右键菜单只在合适节点出现。
- 图标区分人物、地点、规则和 diagnostics。
- 文件正文中的提示语要面向作者，而不是面向开发者。

## 验收标准

- 作者可以启用 Story Bible，并创建、浏览、打开、搜索人物、地点和规则。
- Story Bible 文件保持人可读的 Markdown；插件移除后仍能直接阅读和编辑。
- `.loredock/project.json` 只记录 `story-bible.core` capability，不保存 Card 列表。
- 每张 Card 都有稳定 `id`，重命名不改变 ID。
- Card frontmatter 包含 `schemaVersion: "0.2.0"`，未知或未来版本进入 diagnostics。
- Card frontmatter 不要求 `schema` 字段；Keyword 定义 frontmatter 必须包含 `schema: "story-bible.tag"`。
- `visibility` 和 `status` 可被解析、校验和显示，但不驱动跨版本能力。
- 新建人物、地点和规则 Card 时会自动生成对象主关键词；对象主关键词以 slug 持久化，以当前 `name` 显示。
- 重命名 Card 会生成新的对象主关键词，并保留旧对象关键词用于搜索、筛选和提示。
- 用户可以在 `lore/tags/` 中主动定义普通 Keyword；Keyword 定义是普通 Markdown，插件移除后仍可读。
- 全局 Keyword Catalog 能从 Card frontmatter 和 `lore/tags/**/*.md` 重建，显示关键词列表、说明、分类、计数、source status，并支持输入提示和按关键词筛选。
- Keyword 定义缺失或损坏时，已挂载到 Card 上的 keyword slug 仍保留并降级为 inferred，不自动从 Card frontmatter 中删除。
- 删除普通 Keyword 定义会先进入 `.loredock/trash/resources/story-bible/` 资源垃圾桶，不会改写任何 Card 的 `tags`；仍被使用的 slug 会以 inferred 继续显示和搜索。
- `chapterRefs` 可引用 v0.1 `chapterId`；Manuscript 未启用时不强制解析，启用后能报告缺失章节。
- 损坏 frontmatter 会显示 warning 或 error，但不会拖垮整棵树。
- 搜索能命中 `name`、`aliases`、`tags`、`summary` 和 Markdown 一级标题。
- 搜索能命中 keyword slug、keyword label 和 keyword description。
- 搜索能按 `type`、`visibility`、`status` 和 keyword 过滤。
- 编辑 Card 元数据会更新 frontmatter 和 `updatedAt`，并保留正文 Markdown 不变。
- 从选中文本创建 Card 不会改写原文。
- 删除 Card 会先进入 `.loredock/trash/resources/story-bible/` 资源垃圾桶；资源垃圾桶项目可以还原，也可以永久删除；所有资源垃圾桶操作都不能触碰 `.loredock/trash/manuscript/`。
- 永久删除资源垃圾桶项目需要二次危险确认；取消确认不会删除任何文件。
- 所有写操作都生成 operation plan，并只执行 plan 中声明的文件变化。
- multi-root 下 Story Bible 命令绑定用户选择的目标 folder，路径 workspace-relative，不会写入错误 workspace。
- 测试覆盖启用/取消启用、重复启用、部分启用恢复、模板创建、frontmatter 解析、Card 不要求 `schema` 字段、Keyword 定义要求 `schema: "story-bible.tag"`、自动对象关键词、中文名称对象关键词显示、keyword slug 合法性、keyword slug 冲突、重命名后新旧对象关键词并存、重命名回旧名时复用历史对象关键词、用户定义 Keyword 的 label/description/category 生效、普通关键词多 Card 共享计数、Keyword 定义删除或损坏 degraded、删除 Keyword 定义进入资源垃圾桶、删除 Keyword 定义不改写 Card tags、inferred Keyword、全局 Keyword Catalog、关键词提示、搜索、Markdown 一级标题搜索、keyword slug/label/description 搜索、按 type/visibility/status/keyword 过滤、未知 frontmatter 字段保留、appliesTo 已知 CardType 提示、appliesTo 未知未来 CardType warning、重命名、元数据编辑、删除进入资源垃圾桶、资源垃圾桶资源类型、资源垃圾桶元数据、还原资源垃圾桶项目、永久删除资源垃圾桶项目、永久删除取消确认、重复检测、损坏文件 degraded、chapterRefs 可选校验和从选中文本创建。

## 后续版本接入点

- v0.3 Outline and Scene Cards：场景卡可以通过 `StoryBibleReader` 引用人物和地点；v0.3 不应直接扫描 Story Bible 私有缓存。
