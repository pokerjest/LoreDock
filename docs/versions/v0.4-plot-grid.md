# v0.4 Plot Grid

## 目标

加入 LoreDock 的第一个轻量视觉工作台：剧情矩阵。它把 v0.1 Manuscript、v0.2 Story Bible 和 v0.3 Outline and Scene Cards 已经稳定下来的结构投影到一个可扫读的表格式视图里，让作者能横向检查章节、场景、剧情线、人物、地点、状态和字数进度。

v0.4 的核心目标不是做第二个手稿结构源，也不是提前做 Timeline、Knowledge Graph 或 AI 上下文，而是在本地文件透明和 preview/apply 边界内，提供一个高密度、可过滤、可安全微调的剧情结构视图。

## 产品参考与边界

- 吸收 Dabble Plot Grid 的行列语义：左侧是章节/场景，列是 Plot Lines，单元格用于表达对应章节或场景里的剧情点；但 LoreDock 不做云同步、不把矩阵作为唯一真相，也不自动改写章节正文。参考：[Exploring Dabble's Plot Grid](https://help.dabblewriter.com/en/articles/2692382-exploring-dabble-s-plot-grid)。
- 吸收 Plottr 的可视化时间线、剧情线、场景卡和筛选思路：用户应该能围绕 plotline、人物、地点和状态快速缩小视图；但 v0.4 不做完整时间线、不做跨章节拖拽、不拥有章节顺序 canon。
- 吸收 Scrivener Corkboard/Outliner 的高密度信息组织：状态、标签、摘要、字数和结构位置要能同时扫读；但 v0.4 不做 Compile、不做完整 corkboard，也不把 UI 状态写回用户正文。
- Novelcrafter Codex、Campfire、World Anvil 的 Codex/世界观模块、自定义字段和模板能力只作为后续 v0.5+ 到 v1.5 的参考；v0.4 不新增完整世界观类型系统，不拼装 AI prompt，不建立反链索引。
- Aeon Timeline 的故事时间、人物弧、地点弧和因果一致性继续留给 v0.7 Timeline Engine；v0.4 只处理叙事顺序中的章节和场景矩阵。

## 范围边界

- v0.4 是 Structure capability，能力 ID 固定为 `structure.plot-grid`。
- v0.4 依赖 `manuscript.core` 和 `structure.outline-scenes`；未启用 Manuscript 或 Outline Scenes 时只能提示先启用前置能力，不能创建 Plot Grid 配置或打开矩阵。
- `story-bible.core` 是可选依赖；启用时解析人物、地点、规则和关键词显示名，未启用时只显示场景卡中保存的字符串引用。
- Plot Grid 不直接读写 `manuscript/manifest.json`，不拥有卷、章、章节顺序或章节路径。
- Plot Grid 不直接扫描 `scenes/**/*.md`。所有章节、场景、状态、人物、地点和 `plotlineRefs` 必须来自 `OutlineSceneReader.getSceneProjection()`。
- Plot Grid 不把章节、场景列表、聚合结果或 webview 运行态写入 `.loredock/project.json`。
- v0.4 不创建 `.loredock/indexes/`、`.loredock/snapshots/`、`timelines/` 或 `exports/`。
- v0.4 不自动扫描章节正文，不生成反链，不识别未链接提及，不做一致性检查。
- v0.4 不自动改写章节 Markdown 正文；场景和章节仍通过 v0.3 `chapterRefs` 绑定。
- v0.4 不新增 Story Bible `plotline` CardType。剧情线采用 Plot Grid 轻量轨道配置，正式世界观 schema 扩展留给 v0.6 World Modules 或之后版本。

## 内置矩阵模型

v0.4 内置的是可重建的 Plot Grid Projection，而不是新的 canon 数据源。它由 Manuscript、Scene Projection、Plot Grid Config 和可选 Story Bible 标签解析合成：

```text
Manuscript
  Volume
    Chapter
Scene Projection
  SceneCard -> chapterRefs[] / plotlineRefs[]
PlotGridConfig
  Track[]
  ViewPreferences
PlotGridProjection
  Rows
  Tracks
  Entities
  Diagnostics
```

- Manuscript 是章节 canon：书、卷、章、章节顺序、章节状态、目标字数和章节路径只来自 `ManuscriptReader`。
- Scene Projection 是场景 canon：场景身份、章节绑定、章节内顺序、人物、地点、剧情线引用、POV、冲突、转折、结果和场景状态来自 v0.3 projection。
- Plot Grid Config 只保存矩阵轨道和视图偏好：它不能保存章节副本、场景副本、聚合缓存或用户正文。
- Story Bible 只提供可选标签解析：人物、地点、规则和关键词显示名可以从 `StoryBibleReader` 解析；解析失败时矩阵仍能显示原始引用并报告 diagnostics。
- Plot Grid Projection 是运行时 DTO：每次打开或刷新时从 reader 服务重建，可以序列化给 webview，但不作为持久化数据源。
- Webview 临时状态默认不写入 canon；只有用户显式修改轨道、列显示、行模式、场景剧情线引用或同章节场景顺序时，才走受控 actions。

## 实现

新增本地透明文件结构：

```text
boards/
  plot-grid.json
```

- `boards/plot-grid.json` 是 v0.4 唯一新增的持久化文件，保存轨道配置和视图偏好。
- 缺失 `boards/plot-grid.json` 时，启用 Plot Grid 命令创建默认配置；直接打开 Plot Grid 时可以生成内存默认配置，但不能静默写入磁盘。
- 重复启用命令不能覆盖已有 `boards/plot-grid.json`。
- `boards/` 已在总路线图中预留；v0.4 只使用 `boards/plot-grid.json`，不创建其他 board 文件。
- 文件损坏、路径不安全或 schema 不支持时进入 diagnostics；webview 应进入 degraded 状态，而不是崩溃或清空用户配置。

最小配置示例：

```json
{
  "schemaVersion": "0.4.0",
  "tracks": [
    {
      "id": "main/revenge",
      "label": "复仇主线",
      "color": "#C86464",
      "order": 1,
      "visible": true
    }
  ],
  "view": {
    "rowMode": "scene",
    "visibleColumns": ["status", "pov", "characters", "locations", "wordCount"],
    "showEmptyTracks": true,
    "compact": true
  },
  "updatedAt": "2026-07-07T00:00:00.000Z"
}
```

配置字段：

- `schemaVersion` 必须是 `"0.4.0"`。
- `tracks` 是用户配置的剧情线轨道数组，按 `order` 排序。
- `track.id` 是稳定轨道 ID，必须是合法 keyword slug 风格字符串，可以与场景卡 `plotlineRefs` 中的值直接匹配。
- `track.label` 是显示名，不能为空。
- `track.color` 是可选十六进制颜色；非法颜色进入 warning，并使用默认颜色。
- `track.order` 是正整数；重复 order 进入 warning，projection 用 `order`、`label`、`id` 做稳定兜底排序。
- `track.visible` 控制轨道是否默认显示；隐藏轨道不删除任何场景引用。
- `view.rowMode` 支持 `"scene"` 和 `"chapter"`；默认 `"scene"`。
- `view.visibleColumns` 控制固定信息列，可包含 `status`、`pov`、`characters`、`locations`、`rules`、`wordCount`、`targetWordCount`。
- `view.showEmptyTracks` 控制是否显示当前筛选下没有命中场景的已配置轨道。
- `view.compact` 控制默认密度；具体 CSS 和滚动位置属于 webview 临时状态，不写回配置。
- 未知字段必须保留，不进入 error；v0.4 只改写已知字段，避免破坏后续模板包或用户扩展。

### 启用 Plot Grid

- 新增 `loredock.enablePlotGrid` 命令，通过 preview、confirm、apply 将 `structure.plot-grid` 写入 `.loredock/project.json`，并创建 `boards/plot-grid.json`。
- 启用前必须验证 `.loredock/project.json`、Manuscript capability 和 Outline Scenes capability。
- 如果 `boards/plot-grid.json` 已存在但 capability 未启用，必须先扫描并报告 blocking diagnostics；没有 error 时只写入 capability ID，不覆盖已有文件。
- 启用成功后刷新 Plot Grid 视图入口，并重新运行 v0.4 diagnostics。

### 剧情线轻量轨道

- v0.4 的剧情线不是 Story Bible 卡片，而是 Plot Grid track。
- `track.id` 与场景卡 `plotlineRefs` 中的字符串匹配；一个场景可以出现在多个剧情线轨道下。
- 用户可以从 Plot Grid 创建、重命名、隐藏、删除和排序轨道。
- 删除轨道只删除 `boards/plot-grid.json` 中的配置，不删除场景卡里的 `plotlineRefs`。
- 如果场景卡引用了未配置的 plotline，projection 必须生成 inferred track；inferred track 显示原始 ID，排在已配置轨道之后。
- 用户可以把 inferred track 转为正式配置轨道，设置显示名、颜色和顺序。
- 对场景分配或移除剧情线时，只能通过 `OutlineSceneActions.updateSceneMetadata()` 修改该场景卡的 `plotlineRefs` 和 `updatedAt`。

### Webview

- 新增 `loredock.plotGrid.open` 命令，打开或聚焦单例 Plot Grid webview panel。
- 默认使用 scene-row 模式：章节作为分组行，场景作为可操作行。
- chapter-row 模式用于高层扫描：每个章节聚合其场景的状态、人物、地点、剧情线和字数信息；聚合行可以打开章节或展开场景，但不能直接覆盖多个场景的元数据。
- 表格左侧冻结卷/章/场景列，顶部表头固定。
- 固定信息列显示状态、POV、人物、地点、规则/关键词、章节字数和目标字数；列显隐由 `view.visibleColumns` 控制。
- 剧情线轨道列显示命中该 track 的场景摘要、冲突、转折或结果短文本；同一场景命中多个轨道时可以在多个单元格中出现。
- 筛选栏支持人物、地点、剧情线、状态和文本搜索；筛选只影响当前 webview projection，不默认写回 `boards/plot-grid.json`。
- 空状态必须根据缺失内容给出下一步入口：启用前置能力、创建规划草稿、导入大纲、新建场景卡或创建剧情线轨道。
- 长篇项目中优先信息密度和滚动性能，不使用装饰性画布或低密度卡片瀑布。
- 尽可能支持键盘导航：方向键移动焦点，Enter 打开源文件，Space 或显式按钮切换选中，Escape 清除当前临时筛选。

### Webview Message Contract

Webview 与 extension host 的消息必须使用明确 action type：

- `ready`：webview 初始化完成，请求最新 projection。
- `refresh`：手动刷新 projection。
- `openSource`：打开章节、场景卡或 Story Bible 条目源文件。
- `setFilter`：更新当前 webview 临时筛选。
- `updateTrack`：创建、重命名、隐藏、显示、删除或排序轨道。
- `assignSceneTrack`：给单个场景追加或移除 `plotlineRefs`。
- `reorderScenes`：调整同一章节内的场景顺序。
- `persistViewState`：保存 row mode、可见列和基础视图偏好。

所有来自 webview 的消息都必须验证 workspace、能力启用状态、ID、路径和 action payload；不能信任 webview 传回的文件路径。

### 操作边界

- 点击章节打开章节 Markdown。
- 点击场景打开场景卡 Markdown。
- 点击人物、地点、规则或关键词时，如果 Story Bible 可解析，则打开对应卡片或关键词定义；否则显示不可解析提示。
- 分配剧情线只能改单个场景的 `plotlineRefs`；批量分配留到后续版本。
- 同一章节内拖拽场景顺序时，必须调用 `OutlineSceneActions.reorderChapterScenes(chapterId, sceneIds)`，并走 preview/confirm/apply 或明确撤销边界。
- v0.4 禁止跨章节拖拽场景；如果用户尝试跨章节拖动，UI 必须回弹并提示需要先通过 v0.3 绑定/章节操作调整。
- v0.4 禁止调整章节顺序；章节移动仍由 Manuscript capability 负责。

## 公共接口与扩展点

- v0.4 必须通过 service registry 暴露只读 `PlotGridReader`：
  - `getConfig()`：读取 `boards/plot-grid.json`，缺失时返回内存默认配置。
  - `getProjection(filters?)`：返回 webview 可消费的 `PlotGridProjectionDto`。
  - `listTracks()`：列出 configured 和 inferred tracks。
  - `validateConfig()`：返回 v0.4 diagnostics。
- v0.4 必须通过 service registry 暴露受控 `PlotGridActions`：
  - 启用 Plot Grid。
  - 创建、更新、隐藏、显示、删除和排序轨道。
  - 设置 row mode、可见列和基础视图偏好。
  - 给单个场景分配或移除剧情线。
  - 重新分配同章节场景 order。
  - 所有写操作必须走 preview、confirm、apply。
- `PlotGridProjectionDto` 至少包含：
  - `tracks`：configured 和 inferred tracks，带显示名、颜色、顺序、可见状态和来源。
  - `rows`：章节行与场景行，包含稳定 ID、标题、路径、状态、字数、人物、地点、规则、剧情线、诊断摘要和可打开源类型。
  - `filters`：当前可用筛选候选值，包括人物、地点、剧情线和状态。
  - `entities`：已解析的 Story Bible 条目和关键词显示名映射。
  - `diagnostics`：配置、projection 和引用解析中的 warning/error 摘要。
- v0.4 必须订阅 Manuscript、Outline Scenes 和可选 Story Bible change events：
  - Manuscript `structure/status/metadata/content` 变化刷新章节行、状态和字数。
  - Outline Scenes `structure/metadata/content` 变化刷新场景、剧情线和轨道命中。
  - Story Bible `structure/metadata/content` 变化刷新实体显示名和跳转状态。
- 后续 v0.5 Knowledge Graph 可以读取 Plot Grid projection 的行/轨道关系作为 UI 辅助，但不能依赖 `boards/plot-grid.json` 作为引用 canon。

## 诊断

以下情况必须进入 diagnostics：

- `boards/` 或 `boards/plot-grid.json` 路径不安全，或通过 symlink 解析到 workspace 外。
- Plot Grid config JSON 损坏。
- `schemaVersion` 不是 `"0.4.0"`。
- `tracks` 不是数组。
- `track.id` 缺失、为空、重复或不是合法 keyword slug 风格字符串。
- `track.label` 缺失或为空。
- `track.color` 不是合法十六进制颜色。
- `track.order` 不是正整数，或多个 configured tracks 使用同一个 `order`。
- `track.visible` 不是布尔值。
- `view.rowMode` 不是 `"scene"` 或 `"chapter"`。
- `view.visibleColumns` 包含 v0.4 不支持的列名。
- 场景卡引用了未配置 plotline，生成 inferred track 并报告 info 或 warning。
- Story Bible 启用时，人物、地点、规则或关键词引用无法解析。
- 调整场景顺序时，payload 不属于同一章节或缺失该章节下已有场景。

## 优化

- 从紧凑 projection model 加载矩阵数据，不在每次 webview 渲染时重新解析所有文件。
- Projection 必须确定：同一 workspace 状态、同一 config 和同一筛选条件下，轨道顺序、行顺序和单元格内容顺序必须一致。
- Webview 状态必须可序列化；extension host 只接受明确 action，不接受任意脚本拼装路径。
- 大型项目初版可以全量重建 projection，但 reader 接口要允许后续替换为增量索引。
- 字数可以按打开 projection 时读取章节正文计算；如果计算失败，显示未知并报告 warning，不能阻塞整个矩阵。
- 轨道颜色只作为辅助视觉，不作为唯一状态表达；状态、引用和诊断必须有文字或图标提示。
- 拖拽调整必须有预览或撤销边界；如果 preview/apply 无法流畅支持拖拽，优先提供显式“上移/下移/调整顺序”命令。

## 打磨

- 布局紧凑、可扫读，避免为了好看牺牲信息密度。
- 表头固定，左侧章节/场景列固定。
- 长标题、长人物名和多剧情线引用必须截断或换行，不能撑破单元格。
- 空状态按当前缺口给出少量明确动作，不展示营销式说明页。
- 命令标题使用自然中文，内部 command ID 保持英文稳定。
- QuickPick 条目显示作者可读标题，detail 显示稳定 ID 或相对路径，避免用户误以为标题是身份。
- Diagnostics 应在 webview 顶部有摘要入口，同时仍进入 LoreDock OutputChannel。
- webview 刷新不能丢失当前临时筛选；但未保存的滚动位置、焦点和展开状态不要求跨会话保留。

## 验收标准

- 启用 Plot Grid 后会创建 `boards/plot-grid.json`，并把 `structure.plot-grid` 写入项目 capability。
- 用户能在一个视图里看到章节、场景、剧情线、人物、地点、状态和字数结构。
- scene-row 模式下章节分组和场景顺序与 v0.3 Scene Projection 一致。
- chapter-row 模式下章节聚合信息稳定、可打开源章节，并能展开或定位到场景。
- 用户能创建、重命名、隐藏、显示、删除和排序剧情线轨道。
- 删除轨道不会删除任何场景卡 `plotlineRefs`；相关引用会以 inferred track 继续显示。
- 用户能给单个场景追加或移除剧情线引用，保存后场景卡 frontmatter 更新且未知字段保留。
- 用户能在同一章节内调整场景顺序，且不会破坏章节顺序或跨章节绑定。
- 点击章节、场景卡、人物、地点、规则或关键词项能打开对应源文件；不可解析引用要有明确提示。
- v0.5 可以在不重新设计 v0.4 存储的情况下读取剧情矩阵 projection 辅助建立图谱视图。

## 测试计划

- Config 测试覆盖缺失配置、首次启用创建、重复启用不覆盖、损坏 JSON、未知 schema、重复 track id、非法颜色、重复 order、未知字段保留和 inferred track 生成。
- Projection 测试覆盖 Manuscript 卷章顺序、scene-row、chapter-row、章节分组、未绑定场景、失效章节引用、人物/地点/规则/剧情线/status/word count 字段完整性。
- Story Bible 集成测试覆盖启用和未启用两种状态、可解析实体显示名、不可解析引用 diagnostics 和关键词定义跳转。
- Actions 测试覆盖创建/更新/隐藏/显示/删除/排序轨道、分配/移除场景剧情线、保存 view preferences、同章节 reorder 和跨章节 reorder 拒绝。
- Webview message 测试覆盖 `ready`、`refresh`、`openSource`、`setFilter`、`updateTrack`、`assignSceneTrack`、`reorderScenes` 和 `persistViewState` 的 payload 校验。
- UI 测试覆盖空状态、筛选组合、固定表头、键盘导航、点击打开源文件、刷新后临时筛选保留和 degraded 配置提示。
- 回归测试覆盖 v0.3 场景卡 projection、`plotlineRefs`、Story Bible 引用诊断、资源垃圾桶和 Manuscript 章节移动行为不被 v0.4 破坏。

## 风险

- 第一个 webview 容易膨胀成第二个应用，必须限制为 projection viewer + 少量安全结构编辑。
- 轨道配置和场景卡 `plotlineRefs` 如果边界不清，用户会误以为删除轨道等于删除剧情线 canon。
- 在 preview/undo 体验不成熟时过度依赖拖拽，会让场景顺序修改不够可信。
- chapter-row 聚合如果表达不清，用户会误以为能直接批量覆盖多个场景字段。
- Story Bible 未启用或引用不可解析时，矩阵仍要可用，不能把可选依赖变成硬依赖。
- 字数统计和大项目 projection 如果每次全量计算，可能影响 webview 打开速度；初版要保留未来增量索引替换空间。
