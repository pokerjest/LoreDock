# v0.1 Manuscript Core

## 目标

让 LoreDock 成为一个真正可用的本地起草工具。作者应该能创建小说、创建章节、写 Markdown、追踪进度并导航整本书，而不需要任何世界观或 AI 功能。

## 实现

- 将 Manuscript 作为 capability 挂载到 Kernel。
- 文件结构：

```text
manuscript/
  book-001/
    volume-001/
      chapter-001.md
```

- 在 manifest 中扩展 books、volumes、chapters。
- Activity Bar 中提供 `Manuscript` 树。
- 命令：
  - 新建书
  - 新建卷
  - 新建章节
  - 打开章节
  - 重命名章节
  - 移动章节
  - 删除章节，需要确认
  - 设置章节状态
  - 刷新手稿树
  - 显示写作统计
- 章节状态：
  - `idea`
  - `outline`
  - `draft`
  - `revise`
  - `done`
  - `archived`
- 支持中英文混合字数统计。
- 提供全局项目 notes 文件。

## 优化

- 只在相关文件变化时刷新手稿树。
- v0.1 可以先全量统计字数，但接口要允许后续增量统计。
- 章节顺序必须稳定并写入 manifest。
- 章节 Markdown 不写隐藏插件元数据。

## 打磨

- 默认命名使用自然中文，例如 `第一卷`、`第一章`。
- 树视图要有清楚的空状态。
- 右键菜单只在合适节点出现。
- 状态标签和图标要容易理解。
- 写作统计以 Markdown 报告形式打开。

## 验收标准

- 用户只用 v0.1 就能写完整本小说草稿。
- 章节文件是普通 Markdown，离开 VS Code 也能读。
- 删除章节必须确认，并同步更新 manifest。
- 移动或重命名章节不能丢正文。
- 测试覆盖章节 CRUD、状态变化、排序和字数统计。

## 风险

- 过早加入故事圣经字段。
- 在树视图和 Markdown 工作流稳定前就做自定义编辑器。
- 在大纲和场景还不存在时把 manifest 设计得太复杂。
