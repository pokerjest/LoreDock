# v0.1 Manuscript Core

## 目标

让 LoreDock 成为一个真正可用的本地起草工具。作者应该能创建小说、创建章节、写 Markdown、追踪进度并导航整本书，而不需要任何世界观功能或内置 AI 功能（书目录下的 `agent.md` 是给外部 AI 工具读的静态说明，不是内置 AI）。

## 产品参考与边界

- 吸收 Scrivener Binder 的长篇手稿组织思路：书、卷、章作为核心导航和重排对象。
- 吸收 Dabble、Ulysses、Atticus 的轻量进度反馈：字数、状态和目标差距能帮助作者继续写，但 v0.1 不做复杂习惯追踪。
- 保留 Obsidian 式本地透明文件精神：章节和 notes 都是普通 Markdown，插件移除后仍可读。
- 不吸收 Plottr、Dabble Plot Grid、Campfire、World Anvil 的规划和世界观工作台；这些能力放到 v0.2-v0.7。
- 不吸收 Atticus 或 Scrivener Compile 的导出排版能力；导出放到 v1.1。

## 实现

- 将 Manuscript 作为 capability 挂载到 Kernel。
- `.loredock/project.json` 保持薄 manifest，只记录项目身份、版本和启用 capability；不把 books、volumes、chapters 塞进项目 manifest。
- Manuscript capability ID 固定为 `manuscript.core`。
- v0.1 沿用 v0.0 的目标 workspace folder 解析：单 folder 直接使用，多 folder 时由用户显式选择目标 folder；`enableManuscript` 和所有手稿命令都把 `manuscript/` 与 `.loredock/project.json` 绑定到该 folder，路径一律 workspace-relative，不隐式写入其他 folder。
- 新增 `loredock.enableManuscript` 命令，通过 preview、confirm、apply 将 `manuscript.core` 写入 `.loredock/project.json`，并创建 v0.1 所需的最小手稿文件结构。
- `loredock.enableManuscript` 只在 `.loredock/project.json` 可解析且 validation 通过时执行；manifest 缺失时提示先运行 `loredock.initProject`，manifest degraded 时提示先运行 `loredock.repairProjectManifest`。
- `loredock.enableManuscript` 写入 `.loredock/project.json` 时必须更新项目 manifest 的 `updatedAt`；用户取消 preview 时不能写入 capability、目录或文件。
- `loredock.enableManuscript` apply 时先创建 `manuscript/` 目录和手稿文件，最后写入 `.loredock/project.json`；如果创建手稿文件失败，不能把 `manuscript.core` 写入项目 manifest。
- 如果最后写入 `.loredock/project.json` 失败，但 `manuscript/manifest.json` 和章节文件已经创建成功，不能静默删除这些手稿文件；必须报告“部分启用” diagnostics，并让下一次 `loredock.enableManuscript` 走“手稿文件已存在但 capability 未启用”的恢复路径。
- `loredock.enableManuscript` apply 后必须重新读取并验证 `.loredock/project.json` 和 `manuscript/manifest.json`，失败时报告 diagnostics。
- `loredock.enableManuscript` 复用 v0.0 operation plan：`manuscript/` 等目录列入 `directoriesToCreate`、手稿文件列入 `filesToCreate`、`.loredock/project.json` 列入 `filesToModify`，apply 只执行 plan 中声明过的变化。
- 首次启用 Manuscript 时创建 `manuscript/manifest.json`、`manuscript/notes.md`、默认 `第一本书`、`第一卷` 和 `第一章`，并写入 `manuscript/book-001/agent.md` 与 `manuscript/book-001/volume-001/chapter-001.md`。
- 重复运行 `loredock.enableManuscript` 必须保守处理：不能重复写入 capability ID，不能覆盖现有 `manuscript/manifest.json` 或章节文件；已有 Manuscript 时只刷新/打开 Manuscript 树或报告现有状态。
- 如果 `manuscript/manifest.json` 已存在但 `.loredock/project.json` 尚未启用 `manuscript.core`，`loredock.enableManuscript` 必须先验证现有 Manuscript manifest；验证通过时只写入 capability ID，不覆盖手稿文件，验证失败时只报告 diagnostics。
- `loredock.initProject` 仍只创建 v0.0 最小项目；不会默认创建 `manuscript/`。
- 文件结构：

```text
manuscript/
  manifest.json
  book-001/
    agent.md
    volume-001/
      chapter-001.md
  notes.md
```

- `manuscript/manifest.json` 作为 Manuscript 模块 canon，记录：
  - `schemaVersion: "0.1.0"`
  - manifest：`bookIds`、`nextBookNumber`、`createdAt`、`updatedAt`
  - book：稳定 ID、标题、相对目录、volume ID 列表、`nextVolumeNumber`
  - volume：稳定 ID、标题、所属 book ID、相对目录、chapter ID 列表、`nextChapterNumber`
  - chapter：稳定 ID、标题、所属 volume ID、状态、正文相对路径、`createdAt`、`updatedAt`
  - chapter 可选 `targetWordCount`
- `manuscript/manifest.json` 的最小形状固定为对象表 + 顺序 ID 列表，方便 lookup 并避免实体数组重排造成大 diff：

```json
{
  "schemaVersion": "0.1.0",
  "bookIds": ["book_..."],
  "books": {
    "book_...": {
      "id": "book_...",
      "title": "第一本书",
      "path": "manuscript/book-001",
      "volumeIds": ["volume_..."],
      "nextVolumeNumber": 2
    }
  },
  "volumes": {
    "volume_...": {
      "id": "volume_...",
      "bookId": "book_...",
      "title": "第一卷",
      "path": "manuscript/book-001/volume-001",
      "chapterIds": ["chapter_..."],
      "nextChapterNumber": 2
    }
  },
  "chapters": {
    "chapter_...": {
      "id": "chapter_...",
      "volumeId": "volume_...",
      "title": "第一章",
      "status": "draft",
      "path": "manuscript/book-001/volume-001/chapter-001.md",
      "createdAt": "2026-06-29T00:00:00.000Z",
      "updatedAt": "2026-06-29T00:00:00.000Z",
      "targetWordCount": 3000
    }
  },
  "nextBookNumber": 2,
  "createdAt": "2026-06-29T00:00:00.000Z",
  "updatedAt": "2026-06-29T00:00:00.000Z",
  "trash": {
    "itemIds": [],
    "items": {}
  }
}
```

- `targetWordCount` 是可选正整数字段；未设置时不能写 `null` 占位。设置目标字数时只能写正整数，清除目标时删除该字段，`0`、负数、小数和非数字都拒绝。
- `nextBookNumber`、book `nextVolumeNumber` 和 volume `nextChapterNumber` 是文件名序号计数器，只递增不回退；删除书/卷/章后不能复用已经分配过的落盘序号。
- `trash` 保存回收站索引和删除快照。旧 manifest 缺少 `trash` 时按空回收站读取；回收站条目的 `trashPath` 必须位于 `.loredock/trash/manuscript/` 下。
- 书、卷、章的显示顺序只由父级 ID 列表决定：顶层 `bookIds` 决定书顺序，book 的 volume ID 列表决定卷顺序，volume 的 chapter ID 列表决定章顺序；实体自身不再保存单独 `order` 字段，避免双重真相。
- Manuscript 通过 v0.0 `SchemaRegistry` 注册 `manuscript.manifest` 的 `0.1.0` schema 元数据；实际 manifest validation 由 Manuscript 模块的 validator 执行，未知或未来 `schemaVersion` 进入 degraded state，不自动迁移。
- 在 Activity Bar 注册一个全局 `Manuscript` 树；单 workspace 直接显示手稿内容，多 workspace 时先按 workspace 分组，树节点和命令参数都携带目标 workspace，避免写入错误 folder。
- 命令：
  - 启用 Manuscript
  - 新建书
  - 新建卷
  - 新建章节
  - 打开章节
  - 重命名书
  - 重命名卷
  - 重命名章节
  - 移动章节
  - 上移章节
  - 下移章节
  - 删除书，非空时需要二次确认
  - 删除卷，非空时需要二次确认
  - 删除章节，需要确认
  - 切换手稿树回收站视图
  - 还原回收站项目
  - 永久删除回收站项目
  - 设置章节状态
  - 刷新手稿树
  - 显示写作统计
  - 设置章节目标字数
  - 打开全局手稿 notes
- 章节状态：
  - `idea`
  - `outline`
  - `draft`
  - `revise`
  - `done`
  - `archived`
- 新建章节默认状态为 `draft`。
- 新建书默认创建空 book 目录和 manifest book 记录，不自动创建卷或章节；新建卷默认创建空 volume 目录和 manifest volume 记录，不自动创建章节。空书和空卷允许存在，树视图和统计报告以 0 章、0 字显示。
- 每本书目录必须生成一个 `agent.md`，作为 AI 插件的书级操作说明。该文件不进入 `manuscript/manifest.json`，不参与章节字数统计，也不作为正文 canon；它用于告诉 AI 如何读取 manifest、定位章节、避免直接破坏结构文件，并提醒结构写入必须走 LoreDock preview/apply。
- `agent.md` 必须分为“系统规则（只读）”和“用户自定义规则（可编辑）”两块。系统规则只允许 LoreDock 开发者通过插件或模板迁移更新；用户规则允许用户写入本书的 AI 协作偏好。若用户规则与系统规则冲突，AI 必须先向用户说明冲突并询问确认；获得确认后，本次协作按用户自己的规则执行，但仍不得改写系统规则块。
- 支持中英文混合字数统计。
- 提供全局手稿 notes 文件，固定为 `manuscript/notes.md`，保持普通 Markdown，不做 Story Notes、资料库、反链或上下文推荐。
- 支持删除书和删除卷。空书、空卷只走标准 preview/apply；包含卷或章节的书、包含章节的卷必须在 preview/apply 之外再做一次危险删除确认。删除书、卷、章时先从活跃结构移入回收站，并把可安全访问的书目录、卷目录或章节 Markdown 移动到 `.loredock/trash/manuscript/`；回收站项目可以还原，也可以永久删除并递归删除对应回收站目录。
- 书、卷、章标题必须是非空、非纯空白字符串；新建和重命名时拒绝空标题或纯空白标题并提示用户。标题只影响显示，不影响文件名和稳定 ID。

## 时间戳规则

- 启用 Manuscript、创建书/卷/章、移动章节、删除书/卷/章会更新 `manuscript/manifest.json` 的 `updatedAt`。
- 新建章节时写入 chapter 的 `createdAt` 和 `updatedAt`。
- 重命名章节、移动章节、设置章节状态、设置章节目标字数会更新对应 chapter 的 `updatedAt`。
- 重命名书或卷只更新 `manuscript/manifest.json` 的 `updatedAt`；book 和 volume 在 v0.1 不单独保存时间戳。
- 保存或编辑章节 Markdown 正文不会改写 `manuscript/manifest.json`，避免打字时产生元数据 churn；正文变化通过文件 watcher 触发 `content` event，统计时重新读取文件。

## 字数统计规则

- 中文、日文、韩文等 CJK 字符按单个字符计数。
- 连续英文、数字和下划线按一个词计数。
- Markdown 标题文本参与统计，但标题标记、链接标记、强调标记和列表标记不计入。
- fenced code block 和 inline code 不计入正文统计。
- 标点、空白和纯 Markdown 语法符号不计入。
- v0.1 可以先每次全量统计，但统计接口必须能在后续版本替换为增量统计。

## 公共接口与预留扩展点

- v0.1 必须实现 Kernel 最小 capability service registry：
  - `registerCapabilityService(id, service)`
  - `getCapabilityService<T>(id)`
- v0.1 必须通过 service registry 暴露只读 `ManuscriptReader`：
  - 列出 books、volumes、chapters，并返回稳定 ID、标题、父子关系、状态、相对路径、可选目标字数和稳定顺序
  - 列出回收站条目，并返回稳定 ID、类型、标题、删除时间、原路径和回收站路径
  - 按 chapter ID 解析章节路径
  - 读取章节文本
  - 获取章节状态和稳定顺序
  - 读取章节文本遇到缺失文件或非法路径时返回受控错误，不能抛出未捕获异常
  - 返回只读 DTO，不能把可被外部模块直接修改的 manifest 内部对象引用泄露出去
- v0.1 必须通过 service registry 暴露受控 `ManuscriptActions`：
  - 创建书/卷/章，重命名书/卷/章，移动章节，删除书/卷/章，还原回收站项目，永久删除回收站项目，设置章节状态，设置章节目标字数
  - 所有写操作必须走 preview、confirm、apply
- v0.1 必须增加 manuscript change events：
  - `structure`
  - `status`
  - `metadata`
  - `content`
- event 语义：
  - `structure`：书、卷、章创建，章节移动、删除，以及父级 ID 列表顺序变化。
  - `status`：章节状态变化。
  - `metadata`：书/卷/章标题、章节目标字数、章节路径或章节 `updatedAt` 变化。
  - `content`：章节 Markdown 或 `manuscript/notes.md` 文件内容变化。
  - 一个操作可以触发多个 event，例如跨卷移动章节会触发 `structure` 和 `metadata`。
- v0.1 必须扩展 operation plan 的最小文件操作契约：
  - `moveFile: { from, to }`
  - `deleteFile: { path }`
  - `backupFile: { source, backup }`
  - `moveDirectory: { from, to }`
  - `deleteDirectoryRecursive: { path }`
- 删除章节在章节 Markdown 文件存在且路径安全时会 emit `moveFile`，把文件移动到 `.loredock/trash/manuscript/<trash-id>/`，再从活跃结构中移除章节并写入回收站条目；如果章节文件已经缺失，则只更新 manifest 和回收站索引。
- 删除卷在卷目录存在且路径安全时会 emit `moveDirectory` 到 `.loredock/trash/manuscript/<trash-id>/`，再从活跃结构中移除该卷和其章节。删除书同理移动整个书目录，包含书级 `agent.md`、卷目录和章节文件。还原回收站项目会把快照重新挂回活跃 manifest，并把回收站内容移回原路径；永久删除回收站项目只允许对 `.loredock/trash/manuscript/` 下的对应目录执行递归删除。
- 稳定 ID 类型预留：
  - `BookId`
  - `VolumeId`
  - `ChapterId`
- `BookId`、`VolumeId`、`ChapterId` 由 Kernel 或统一 ID utility 生成，在 `manuscript/manifest.json` 内必须唯一；生成后不随标题或文件名变化而改变，重命名和移动都不改 ID。检测到重复 ID 进入 diagnostics（见 Manuscript 诊断）。

## Manuscript 诊断

- `manuscript/manifest.json` 缺失、JSON 损坏、`schemaVersion` 不是 `"0.1.0"`、ID 列表引用不存在实体、对象表 key 与实体 `id` 不一致、volume 的 `bookId` 与所属 book 列表不一致、chapter 的 `volumeId` 与所属 volume 列表不一致、重复 ID、重复章节路径、非法章节状态、非法 `targetWordCount`、`manuscript/notes.md` 缺失或路径异常、章节正文路径缺失、路径是绝对路径、路径不在 `manuscript/` 下或指向 workspace 外，都必须进入 diagnostics。
- 每本书 `agent.md` 的只读系统规则块缺失或被改写时必须进入 diagnostics；用户自定义规则块允许用户编辑，不参与只读校验。
- Manuscript manifest 不可解析或 schemaVersion 不支持时，Manuscript 树进入 degraded state：允许打开 diagnostics 和普通 Markdown 文件，但禁用会写入 manifest 的 Manuscript actions。
- 单个章节 Markdown 文件缺失时，树仍显示该章节并标记 warning；打开章节时提示文件缺失，不自动重建正文文件。
- v0.1 只报告 orphan manuscript Markdown 文件，不自动删除或收编；orphan 指位于 `manuscript/` 下但既不是 manifest 章节路径、也不是 `manuscript/notes.md`、也不是任一书目录下 `agent.md` 的 Markdown 文件。自动修复留到后续 Consistency Lab 或维护命令。

## 章节移动与删除语义

- 同一 volume 内移动章节只更新该 volume 的 chapter ID 列表位置，不移动 Markdown 文件。
- 跨 volume 移动章节必须从原 volume 的 chapter ID 列表移除，并插入目标 volume 的 chapter ID 列表，同时更新章节所属 volume ID；如果目标 volume 对应不同目录，则使用 `moveFile` 移动章节 Markdown 文件。
- 跨 volume 移动时优先保留章节文件 basename；如果目标目录已有同名文件，不能覆盖目标文件，必须在目标目录按单调序号分配新的 `chapter-NNN.md` basename，并在 operation plan 中展示路径变化。
- 移动章节不能改写正文内容，不能改变 chapter ID。
- 移动失败时必须保持原 manifest 和原章节文件可用；不能留下 manifest 指向不存在文件的状态。
- 删除章节必须 preview、confirm、apply；确认后如果原 Markdown 文件存在，先创建回收站条目，再通过 `moveFile` 移入 `.loredock/trash/manuscript/<trash-id>/`，同时从活跃结构中移除 chapter；如果原文件已经缺失，则只更新 manifest 和回收站索引。
- 删除空书和空卷只需要标准 preview/apply；删除非空书或非空卷必须在 preview/apply 之外再做一次危险删除确认。删除书或卷时优先通过 `moveDirectory` 把整个书目录或卷目录移入回收站，因此目录内的章节、`agent.md` 和附加资料会一起保留。
- 手稿树标题栏必须提供回收站切换按钮。活跃视图显示书、卷、章和 notes；回收站视图显示已删除条目。回收站条目右键可以还原或永久删除；还原会拒绝覆盖已存在目标路径，永久删除通过 `deleteDirectoryRecursive` 递归删除对应 `.loredock/trash/manuscript/<trash-id>/` 目录，并从 manifest 回收站索引移除。
- 所有手稿文件写入，以及 `moveFile`、`moveDirectory`、`deleteFile`、`deleteDirectoryRecursive`、`backupFile`，都必须经过统一写入层（在 v0.0 `SafeFileWriter` 基础上扩展 move/delete/backup 语义）并复用 v0.0 路径校验：对源路径和目标路径都拒绝绝对路径、`..` 逃逸、跨 workspace 写入和 symlink 逃逸；正文移动只允许从目标 workspace folder 内 `manuscript/` 下移动到 `manuscript/` 或 `.loredock/trash/manuscript/`，递归删除只允许作用于 `.loredock/trash/manuscript/` 下的路径。
- 移入回收站失败时必须保持 `manuscript/manifest.json` 与原文件一致：最终要么条目已从活跃 manifest 移除且文件或目录已移动到回收站，要么两者都保留；不能留下 manifest 已移除但文件仍在、或文件已移动但 manifest 仍引用的中间状态。

## 后续版本接入点

- v0.2 Story Bible：故事元素可选保存 `chapterRefs`，但不扫描正文、不生成反链。
- v0.3 Outline and Scene Cards：大纲导入通过 `ManuscriptActions` 生成卷和章；场景卡使用 `chapterId` 绑定章节。
- v0.4 Plot Grid：只读取 `ManuscriptReader` 和场景卡 projection，不拥有章节顺序 canon。
- v0.5 Knowledge Graph：通过 `ManuscriptReader` 扫描章节，引用索引写到 `.loredock/indexes/`，不改手稿正文。
- v0.7 Timeline Engine：事件用 `chapterRefs`、`sceneRefs` 连接手稿与时间线。
- v0.8 Consistency Lab：复用 Manuscript diagnostics 检查缺失章节、orphan 文件、重复 ID 和顺序断裂。
- v0.9 Writing Desk：订阅当前 editor 和 manuscript change events，显示当前章节上下文，但不拥有 canon。
- v1.1 Compile：通过 `ManuscriptReader` 的稳定书、卷、章顺序组稿，导出永远不修改手稿。
- v1.2 Snapshots：挂到 operation apply 前，为删除、移动、修复和导出创建快照。
- v1.3 Assistant：只读取上下文并写 pending suggestions；接受建议时走 diff/preview，不直接改章节。

## 优化

- 只在相关文件变化时刷新手稿树。
- v0.1 可以先全量统计字数，但接口要允许后续增量统计。
- 章节顺序必须稳定并写入 `manuscript/manifest.json`。
- 章节 Markdown 不写隐藏插件元数据。
- 字数统计报告只包含书/卷/章汇总、状态汇总、目标差距和空章节提示；目标差距只在 chapter 有 `targetWordCount` 时显示，不做日历、streak、驾驶舱或复杂目标系统。

## 打磨

- 默认命名使用自然中文，例如 `第一本书`、`第一卷`、`第一章`。
- 书、卷、章落盘名使用稳定可迁移的 ASCII 序号，例如 `book-001/volume-001/chapter-001.md`；序号在所属目录内单调递增分配，删除后不复用已用过的序号，避免历史文件名被新对象占用；文件名不随标题改变，同一目录内移动不改名，跨目录移动只在目标目录 basename 冲突时重新分配章节文件名。
- 全局手稿 notes 的显示名可以是自然语言，但落盘路径固定为 `manuscript/notes.md`。
- 树视图要有清楚的空状态。
- 右键菜单只在合适节点出现。
- 状态标签和图标要容易理解。
- 写作统计以 Markdown 报告形式打开。

## 验收标准

- 用户只用 v0.1 就能写完整本小说草稿。
- 章节文件是普通 Markdown，离开 VS Code 也能读。
- 删除书、卷、章必须先进入回收站；回收站视图可切换查看，回收站中可以右键还原，也可以永久删除并递归删除对应 trash 目录。
- 移动或重命名章节不能丢正文。
- 设置章节目标字数会更新 chapter 的 `targetWordCount`，并反映在下一次写作统计报告中。
- `loredock.enableManuscript` 首次启用、取消启用、重复启用和“手稿文件已存在但 capability 未启用”的恢复路径都有测试覆盖；取消启用不写任何文件，重复启用不覆盖现有手稿文件。
- `loredock.enableManuscript` 在手稿文件创建成功但项目 manifest 写入失败时会报告“部分启用” diagnostics，下一次运行能通过既有恢复路径继续启用。
- 重命名书和重命名卷会更新树显示与 `manuscript/manifest.json`，不改写章节正文。
- `ManuscriptReader` 返回稳定 ID、路径和顺序。
- `ManuscriptActions` 所有写操作都生成 operation plan。
- manuscript change events 在结构、状态、metadata 和章节/notes 文件内容变化时触发。
- 测试覆盖 manuscript manifest 创建、解析、损坏诊断、缺失文件诊断、章节 CRUD、状态变化、排序和字数统计。
- multi-root 下 `enableManuscript` 和手稿命令绑定用户选择的目标 folder，路径 workspace-relative，不会写入错误 workspace。
- `moveFile`/`moveDirectory`/`deleteFile`/`deleteDirectoryRecursive`/`backupFile` 拒绝绝对路径、`..` 逃逸、跨 workspace 和 symlink 逃逸；移入回收站失败后 manifest 与文件保持一致，无悬挂引用或孤儿文件。
- `BookId`/`VolumeId`/`ChapterId` 由统一 utility 生成且项目内唯一，重命名和移动不改 ID，重复 ID 进入 diagnostics。
- 新建章节默认状态为 `draft`；新建或重命名拒绝空标题与纯空白标题。
- `targetWordCount` 只接受正整数或清除字段；跨卷移动遇到目标文件名冲突时不会覆盖文件，会分配新的 `chapter-NNN.md` 并在 preview 中展示。
- Manuscript 通过 `SchemaRegistry` 注册 `0.1.0` schema 元数据；未知或未来版本进入 degraded state，不自动迁移。

## 风险

- 过早加入故事圣经字段。
- 在树视图和 Markdown 工作流稳定前就做自定义编辑器。
- 在大纲和场景还不存在时把 manifest 设计得太复杂。
- 把 Dabble/Plottr 的 Story Notes、Plot Grid、visual timelines 或 scene cards 提前做进 v0.1。
- 把 Obsidian 风格反链、图谱或未链接提及提前做进 v0.1。
