# v0.3 Outline and Scene Cards

## 目标

把 LoreDock 从“手稿 + 故事圣经”推进到可维护长篇结构规划的阶段。v0.3 把大纲作为结构骨架的规划入口，把场景卡作为骨架上的稳定关节，让作者能在本地 Markdown 中规划卷、章、场景、Beat、人物、地点和冲突转折，而不需要进入重型视觉画布。

v0.3 的核心目标不是提前做 Plot Grid，而是先稳定后续 Plot Grid、Knowledge Graph、Timeline 和 Assistant 都会依赖的结构骨架和场景级 canon。

## 产品参考与边界

- 吸收 Scrivener 的 Binder、Outliner 和 Corkboard 思路：大纲和场景卡应该能支撑非线性规划、快速跳转和章节级组织；但 v0.3 不做完整 Corkboard Webview、不做拖拽卡片板，也不做 Compile。
- 吸收 Manuskript 的本地开源、雪花法和线性大纲精神：大纲文件必须是普通 Markdown，用户离开插件也能读；但 v0.3 不内置复杂写作方法模板，方法包留到 v1.5。
- 吸收 Plottr 和 Dabble 的场景、剧情线和 Plot Grid 意识：场景卡要预留 `plotlineRefs`、人物、地点、状态和转折信息；但多轨剧情矩阵、拖拽排序和可视化故事线属于 v0.4。
- 吸收 Novelcrafter Codex 的场景关联资料思路：场景卡可以引用 v0.2 Story Bible 的人物、地点和关键词，形成后续 AI 上下文与一致性检查的地基；但 v0.3 不拼装 AI prompt，不接 provider，不自动改写正文。
- Campfire 和 World Anvil 的模板、世界观模块和百科结构只作为短提示模板参考；v0.3 不新增势力、物品、事件、地图、公开/隐藏发布权限或关系网。
- Aeon Timeline 的故事时间、人物弧、地点弧和因果一致性放到 v0.7 Timeline Engine；v0.3 只保存场景在章节中的叙事顺序。

## 范围边界

- v0.3 是 Structure capability，能力 ID 固定为 `structure.outline-scenes`。
- v0.3 依赖 `manuscript.core`；未启用 Manuscript 时只能提示先启用手稿，不能创建场景卡或导入大纲。
- `story-bible.core` 是可选依赖；启用时校验人物、地点和关键词引用，未启用时只做字符串格式校验。
- v0.3 不直接读写 `manuscript/manifest.json`。任何卷、章创建或章节结构变化必须通过 Manuscript 公开 actions 执行。
- v0.3 不把大纲、场景列表或 projection 写入 `.loredock/project.json`；项目 manifest 仍只记录启用 capability。
- v0.3 不创建 `.loredock/indexes/`、`.loredock/snapshots/`、`boards/`、`timelines/` 或 `exports/`。
- v0.3 不自动扫描章节正文，不生成反链、不识别未链接提及、不做一致性检查。
- v0.3 不自动改写章节 Markdown 正文；场景卡和章节通过 `chapterRefs` 绑定，不通过正文隐藏元数据绑定。

## 内置骨架模型

v0.3 内置的不是一份独立大纲树，也不是第二份手稿 manifest，而是一个可重建的 Structure Skeleton。它把 Manuscript、Scene Cards 和 Outline Markdown 合成为同一组运行时 projection，但 UI 上要区分“已落地骨架”“绑定到骨架的场景卡”和“尚未导入的规划草稿”：

```text
Book
  Volume
    Chapter
Scenes
  SceneCard -> chapterRefs[]
PlanningDraft
  Volume / Chapter / Scene / Beat
```

- Manuscript 是落稿骨架的 canon：书、卷、章、章节顺序和章节路径只来自 `ManuscriptReader`。
- Scene Card 是场景骨架的 canon：场景身份、章节绑定、章节内顺序、人物、地点、剧情线、冲突、转折和结果来自 `scenes/**/*.md` frontmatter。
- Outline Markdown 是规划草图和导入入口：它可以描述尚未落地的卷、章、场景和 Beat，但导入后不成为唯一真相。
- Structure Skeleton 是运行时 projection：每次从 ManuscriptReader、场景卡 scanner 和 outline parser 重建，不写入独立数据库或 manifest。
- Outline Tree 展示这组 projection，而不是只展示文件列表。主骨架显示已落地卷章，并在章节下内嵌绑定到该章节的场景卡；未绑定或失效绑定的场景卡显示在“未绑定场景卡”兜底分组；尚未导入的大纲显示在“规划草稿”分组，作为可预览导入的来源，而不是第二套结构。
- Beat 在 v0.3 不作为独立持久化实体。导入时可以写入场景卡正文；导入 preview 可以从大纲源展示 Beat，但后续 Plot Grid 不依赖 Beat 作为 canon。
- 大纲修改后不会自动同步改写章节或场景卡。重新导入必须走 preview，明确显示新增、复用、跳过或可能冲突的结构项。
- 场景卡可以保存 `sourceOutline` 和 `sourceLine` 作为弱来源关系，用于幂等导入和跳回源大纲；它不能替代 `id`、`chapterRefs` 或 `order`。

## 实现

新增本地透明文件结构：

```text
outlines/
  main.md
scenes/
  scene-001.md
```

- `outlines/` 存放人可读大纲 Markdown。大纲文件是导入源和作者自由规划区，不是机器索引，也不是 Structure Skeleton 的唯一数据源。
- `scenes/` 存放场景卡 Markdown。场景卡是 v0.3 的场景级 canon；文件名不是身份，`id` 才是身份。
- 默认创建的场景卡文件使用 `scene-NNN.md`，在 `scenes/` 下按单调序号分配；删除后不复用旧序号。
- v0.3 scanner 必须读取 `scenes/**/*.md`，允许用户自行整理子目录；新建命令默认写入 `scenes/` 根目录。
- 场景卡删除不能永久删除文件，必须移入 `.loredock/trash/resources/outline-scenes/<trash-id>/`，并写入 `trash-item.json`。
- 不引入 `scenes/manifest.json`。场景列表、排序和 projection 都从场景卡 frontmatter 与 ManuscriptReader 重建。

### 启用结构规划

- 新增 `loredock.enableOutlineScenes` 命令，通过 preview、confirm、apply 将 `structure.outline-scenes` 写入 `.loredock/project.json`，并创建 `outlines/` 和 `scenes/`。
- 启用前必须验证 `.loredock/project.json` 和 Manuscript capability。项目清单缺失时提示先初始化项目；Manuscript 未启用时提示先运行 `loredock.enableManuscript`。
- 如果 `outlines/` 或 `scenes/` 已存在但 capability 未启用，必须先扫描并报告 blocking diagnostics；没有 error 时只写入 capability ID，不覆盖现有文件。
- 重复运行启用命令不能重复写入 capability ID，不能覆盖 `outlines/` 或 `scenes/` 中已有文件。
- 启用成功后刷新 Outline Tree，并重新运行 v0.3 diagnostics。

### 大纲格式

规划草稿是可变粒度 outline draft fragment，不再要求每个文件都写完整卷、章、场景树。文件开头、首个标题前可以声明 Markdown 指令：

```markdown
@scope book
@include ./volume-01.md
```

- `@scope` 支持 `book`、`volume`、`chapter`、`scene`，也接受中文别名 `书`、`卷`、`章`、`场景`；未声明时按旧版 `book` 解析。
- `@include ./relative.md` 包含更小粒度的规划草稿，路径相对当前文件，且必须留在 `outlines/` 内。
- 指令必须位于文件开头、首个标题前；重复 scope、未知 scope、标题后的指令、缺失 include、越界 include、循环 include 和反向包含都进入 diagnostics。
- include 只允许大粒度包含小粒度：`book` 可包含 `volume/chapter/scene`，`volume` 可包含 `chapter/scene`，`chapter` 可包含 `scene`。
- parser 必须跳过 YAML frontmatter、fenced code block 和 HTML block；模板说明用 HTML comment 保存，不能被导入成结构。

不同 scope 使用相对标题语义：

- `book`：`#` 表示卷，`##` 表示章节，`###` 表示场景，`####+` 作为当前最近节点下的备注/Beat。
- `volume`：`#` 表示卷标题，`##` 表示章节，`###` 表示场景；没有 `#` 时使用文件名作为卷标题。
- `chapter`：`#` 表示章节，`##` 表示场景，`###+` 作为当前最近场景或章节下的备注/Beat。
- `scene`：`#` 表示场景；`##+` 只是场景正文小节，不创建结构层级；列表项仍作为 Beat。
- `-`、`*` 或 `+` 开头的列表项表示当前最近场景、章节或卷下的 Beat/备注。
- 空标题进入 warning；解析时使用 `未命名卷`、`未命名章节` 或 `未命名场景` 作为临时显示名，但导入 preview 必须标出。
- 相邻重复标题允许存在，不自动合并；导入幂等不能只依赖标题，必须结合源文件路径和源行号。
- parser 输出必须确定：同一文件内容、同一换行格式和同一 workspace 状态下，节点顺序、临时 ID 和预览结果必须一致。
- 原始大纲文件永远保留，导入不会改写大纲 Markdown。
- 新建规划草稿模板必须先 QuickPick 选择书籍、卷、章或场景粒度，再生成对应模板。
- 规划草稿是普通 Markdown 源文件，用户可以右键删除；删除必须走 preview/apply，取消后不能删除文件。

### 大纲导入

- 新增 `loredock.outlineScenes.importOutline` 命令，只导入 workspace 内 `outlines/**/*.md` 文件。
- 导入命令必须先展示单一 operation preview，明确列出将复用或创建的卷、章节、场景卡和文件路径。
- `book` 草稿按完整书籍规划导入；`volume` 草稿可新建卷，或选择已有卷追加章节/场景；`chapter` 草稿可选择已有章节追加场景，或选择已有卷创建章节；`scene` 草稿可选择已有章节绑定场景卡，或创建章节后绑定。
- 导入 preview 是唯一允许选择或创建缺失父级的位置；不能根据缺失父级静默创建 `未归类卷` 或 `未归类章节`。
- 用户取消 preview 时不能创建卷、章节、场景卡、目录、trash metadata 或任何中间文件。
- 用户确认后，卷和章只能通过 Manuscript 公开 actions 创建；Structure capability 不能直接改写 `manuscript/manifest.json`。
- Manuscript capability 必须提供窄接口准备批量 outline 导入；输入可以表达新建卷/章，也可以通过稳定 ID 复用已有卷/章，由 Manuscript 自己生成和应用 manifest/file changes。
- 导入创建场景卡时，必须等待 Manuscript 返回稳定章节 ID 后再写入 `chapterRefs`。
- 重复导入同一大纲应尽可能幂等：已由同一 outline source file + source line 创建过的场景卡不重复创建；同名章节是否复用必须在 preview 中显示。
- 幂等元数据不能写入手稿正文。允许在场景卡 frontmatter 保存 `sourceOutline` 和 `sourceLine`，用于识别导入来源；include 进来的场景必须保存自己的来源文件，而不是根大纲文件。
- 导入中任一步失败时，最终状态必须可诊断：不能留下场景卡指向不存在章节，不能让 manifest 已创建章节但场景卡批量缺失且无错误报告。

### 场景卡格式

场景卡使用 Markdown + YAML frontmatter。frontmatter 是结构化元数据，正文 Markdown 是作者自由书写区。

最小示例：

```markdown
---
schemaVersion: "0.3.0"
id: "scene_..."
title: "屋顶谈判"
chapterRefs:
  - "chapter_..."
order: 1
pov: "吴烬"
locationRefs:
  - "location/black-tower"
characterRefs:
  - "character/wu-jin"
plotlineRefs:
  - "main/revenge"
conflict: "吴烬必须决定是否暴露能力。"
turn: "林凛发现他说谎。"
outcome: "两人暂时结盟，但互相保留筹码。"
status: "outline"
createdAt: "2026-07-02T00:00:00.000Z"
updatedAt: "2026-07-02T00:00:00.000Z"
---

## 场景目的

## Beats

## 备注
```

场景卡 frontmatter 字段：

- `schemaVersion` 必须是 `"0.3.0"`。
- `id` 是项目内唯一稳定场景 ID，生成后不随标题、文件名、章节或顺序改变。
- `title` 是非空字符串，显示名以它为准，不以文件名为准。
- `chapterRefs` 是 Manuscript 稳定章节 ID 数组，可以为空，也可以绑定多个章节；不能保存章节标题或路径。兼容读取旧 `chapterId`，但新写入必须使用 `chapterRefs`。
- `order` 是场景卡在绑定章节中的显示顺序，从 `1` 开始；多章节绑定时同一个 `order` 会用于所有绑定章节。重复 order 进入 warning，projection 用 `order`、`title`、`path` 做稳定兜底排序。
- `pov` 是自由短文本；v0.3 不强制它必须引用人物，但如果值能匹配 Story Bible Card 或 keyword，UI 可以提示跳转。
- `locationRefs` 是字符串数组，允许保存 v0.2 地点 Card ID 或 keyword slug。
- `characterRefs` 是字符串数组，允许保存 v0.2 人物 Card ID 或 keyword slug。
- `plotlineRefs` 是字符串数组，v0.3 只做字符串与 keyword slug 级校验；正式 plotline CardType 留到 v0.4 或 v0.6。
- `conflict`、`turn`、`outcome` 是短文本字段，可以为空字符串。
- `status` 使用 `idea`、`outline`、`draft`、`revise`、`done`、`archived`，默认 `outline`。
- `createdAt` 和 `updatedAt` 必须是 ISO 时间戳字符串。
- 可选 `sourceOutline` 保存导入来源大纲相对路径，可选 `sourceLine` 保存源场景标题行号。
- 未知 frontmatter 字段必须保留，不进入 error；场景卡元数据编辑只能改写 v0.3 已知字段，避免破坏未来模板包或用户扩展。

场景卡正文模板必须短小实用，只提供“场景目的、Beats、备注”等提示，不把长篇内容塞进 frontmatter。

### 场景卡操作

- 新增 `loredock.outlineScenes.createSceneCard`：先选择 0..N 个绑定章节，再输入场景标题，创建场景卡。
- 新增 `loredock.outlineScenes.bindScenesToChapter`：作为章节节点 inline 主操作，选择已有场景卡并追加绑定到该章节。
- 新增 `loredock.outlineScenes.bindSceneToChapters`：作为场景卡右键操作，选择现有章节并追加到该场景卡 `chapterRefs`。
- 新增 `loredock.outlineScenes.createChapterAndBindScene`：作为场景卡右键操作，先在选定卷中新建章节，再把新章节 ID 追加到该场景卡 `chapterRefs`。
- 保留 `loredock.outlineScenes.createSceneCardFromChapter` 作为辅助命令，语义仍是“新建场景卡并绑定此章节”，但不能作为章节节点的主要按钮。
- 新增 `loredock.outlineScenes.openSceneCard`：打开场景卡 Markdown。
- 新增 `loredock.outlineScenes.editSceneMetadata`：通过 QuickPick/InputBox 编辑标题、章节、order、pov、人物、地点、plotline、冲突、转折、结果和状态；保存必须 preview/apply。
- 新增 `loredock.outlineScenes.deleteSceneCard`：删除场景卡时移入 v0.3 资源垃圾桶，不永久删除。
- 新增 `loredock.outlineScenes.restoreTrashItem` 和 `loredock.outlineScenes.permanentlyDeleteTrashItem`：还原拒绝覆盖已有路径，永久删除需要危险确认。
- 调整场景章节绑定只改 `chapterRefs`、必要时重排 `order` 和 `updatedAt`，不移动文件。
- 同一章节内调整 order 可以先用 QuickPick/数字输入实现；拖拽排序留到 v0.4。

## 优化

### Outline Tree

- 在 LoreDock activity bar 增加 Outline/Structure 树视图，view ID 固定为 `loredock.outlineScenes.tree`。
- 未启用时显示启用入口；启用后默认显示 Structure Skeleton 主骨架，并提供“结构骨架”、“未绑定场景卡”、“规划草稿”和“资源垃圾桶”入口。
- 主骨架的卷和章来自 ManuscriptReader；章节下显示绑定到该章节的场景卡，语义是“场景卡引用了章节”，不是“章节派生了场景卡”。未绑定或失效绑定场景卡在兜底分组展示。
- “规划草稿”是结构骨架的导入源，展示 `outlines/**/*.md`，默认折叠在主骨架下方，避免用户误以为有两套可编辑结构。
- 规划草稿文件节点是叶子节点，摘要显示草稿粒度和卷/章/场数量，例如 `章大纲 · 1 章 3 场`；点击打开 Markdown，右键可“预览导入大纲到结构骨架”或“删除规划草稿”。
- 大纲 parser 的卷、章、场景和 Beat 细节进入导入 preview，不在 Outline Tree 中展开成第二棵结构树；这些草稿节点不参与 scene projection，不被 v0.4 当作 canon。
- 结构骨架里的卷和章必须能复用 Manuscript actions：卷节点可新建章节、重命名、删除；章节节点可打开、重命名、移动、删除，并可绑定已有场景卡。
- 如果场景卡引用的 `chapterRefs` 全部不存在，显示在“未绑定场景卡”兜底分组，并进入 diagnostics；如果只是一部分引用失效，仍在有效章节下显示并报告 warning/error。
- 树图标必须区分规划草稿文件、卷、章、场景、Beat、诊断和垃圾桶项目。
- 点击大纲节点打开源 Markdown 并定位到对应行；点击场景卡打开场景卡；右键可跳转到绑定章节、人物、地点或关键词。
- TreeView 只做轻量导航和命令入口，不承载拖拽画布或复杂编辑状态。

### 跳转与引用

- 场景卡到章节：通过 `ManuscriptReader.resolveChapterPath(chapterRef)` 打开一个或多个绑定章节。
- 章节到场景卡：从当前章节 ID 查找 `chapterRefs` 包含该 ID 的场景卡列表。
- 场景卡到 Story Bible：启用 Story Bible 时，通过 `StoryBibleReader` 解析 `characterRefs`、`locationRefs` 和 keyword slug；未找到引用时显示 warning。
- v0.3 不在章节正文中插入场景链接，也不自动把选中文本替换为链接。
- v0.5 Knowledge Graph 可以后续扫描正文并建立反链，但不能要求 v0.3 预写隐藏标记。

### 公共接口与预留扩展点

- v0.3 必须通过 service registry 暴露只读 `OutlineSceneReader`：
  - `listOutlines()`：列出 `outlines/**/*.md`，返回标题、路径和解析状态。
  - `parseOutline(path)`：解析单个大纲 Markdown，返回 `scope`、`includes`、卷、章、场景、Beat、来源文件、源行号和 diagnostics。
  - `getStructureSkeleton()`：返回 Outline Tree 使用的完整骨架 projection，包括 Manuscript 卷章、已落地场景、未落地 outline draft 节点、来源路径、源行号和诊断摘要。
  - `listScenes(query?)`：列出场景卡 DTO，支持按章节引用、`status`、人物、地点和 plotline 过滤。
  - `getScene(sceneId)`：按稳定 ID 读取场景 DTO。
  - `resolveScenePath(sceneId)`：解析场景卡相对路径。
  - `readSceneText(sceneId)`：读取场景卡正文，失败时返回受控错误。
  - `getSceneProjection()`：返回 v0.4 Plot Grid 可消费的紧凑 projection，包括章节顺序、场景顺序、标题、状态、人物、地点、plotline、路径和诊断摘要。
  - `listTrashItems()`：列出 v0.3 资源垃圾桶条目。
- v0.3 必须通过 service registry 暴露受控 `OutlineSceneActions`：
  - 启用结构规划。
  - 创建规划草稿模板，可指定 `book/volume/chapter/scene` 粒度，默认 `book`。
  - 删除规划草稿。
  - 导入大纲，可传入复用或创建父级的 target options。
  - 创建场景卡并绑定章节。
  - 绑定已有场景卡到章节。
  - 绑定场景卡到现有章节。
  - 新建章节并绑定场景卡。
  - 从章节节点辅助创建绑定到该章节的场景卡。
  - 更新场景卡元数据。
  - 删除、还原和永久删除场景卡。
  - 重新分配同章节场景 order。
  - 所有写操作必须走 preview、confirm、apply。
- v0.3 必须增加 structure change events：
  - `outline`：规划草稿文件创建、修改、删除。
  - `structure`：场景卡创建、删除、章节绑定变化或 order 变化。
  - `metadata`：场景卡 frontmatter 字段变化。
  - `content`：场景卡 Markdown 正文变化。
- 后续 v0.4 Plot Grid 只能读取 `OutlineSceneReader.getSceneProjection()` 和使用 `OutlineSceneActions` 调整安全范围内的场景顺序；不能直接拥有章节顺序 canon。

### 诊断

以下情况必须进入 diagnostics：

- `outlines/`、`scenes/` 或 v0.3 trash 路径不安全，或通过 symlink 解析到 workspace 外。
- 场景卡 frontmatter 缺失、损坏或 `schemaVersion` 不是 `"0.3.0"`。
- 场景卡 `id` 缺失、为空或重复。
- `title` 缺失或为空。
- `chapterRefs` 不是字符串数组，或在 Manuscript 启用状态下引用找不到的章节。空数组允许存在，表示未绑定场景卡。
- `order` 不是正整数。
- 同一章节引用下多个场景卡使用同一个 `order`。
- `locationRefs`、`characterRefs` 或 `plotlineRefs` 不是字符串数组。
- Story Bible 启用时，人物或地点引用无法解析为对应类型 Card 或有效 keyword。
- `status` 不在允许枚举中。
- `createdAt` 或 `updatedAt` 不是 ISO 时间戳字符串。
- 大纲 parser 遇到空标题、非法层级跳跃、无法归属的 Beat、未知 scope、重复 scope、标题后的指令、坏 include 或 include containment 反转。
- trash metadata 缺失、损坏、目标路径不安全或还原目标已存在。

## 打磨

- 大纲解析宽容但确定；错误以 diagnostics 和 preview 呈现，不让单个坏文件拖垮整棵树。
- 保留原始大纲文本；导入不会改写 outline 文件。
- 大纲导入尽可能支持幂等，重复导入前必须在 preview 中说明复用、跳过或新增的对象。
- 除非用户确认生成，否则不能修改 manuscript、scenes 或 project manifest。
- 预览文档明确列出会创建什么。
- 取消导入不会留下半成品文件。
- 场景卡模板保持短小实用。
- 树图标区分卷、章、场景和 Beat。
- 空状态给出下一步入口：新建规划草稿、导入大纲、绑定已有场景卡或新建场景卡。
- 命令标题使用自然中文，内部 command ID 保持英文稳定。
- QuickPick 条目显示作者可读标题，detail 显示稳定 ID 或相对路径，避免用户误以为标题是身份。
- 长篇项目中，树刷新可以先全量扫描，但接口和 projection 要允许后续替换为增量索引。

## 验收标准

- Markdown 大纲可以在显式确认后生成手稿结构。
- 用户不使用视觉板，也能维护场景。
- 场景卡可以引用 v0.2 创建的人物和地点。
- 场景卡通过稳定 `chapterRefs` 绑定章节，章节重命名不破坏绑定；一张场景卡可以不绑定章节，也可以绑定多个章节。
- 删除场景卡先进入 v0.3 资源垃圾桶，可以还原，也可以在二次确认后永久删除。
- v0.4 可以通过 scene projection 读取章节、场景、人物、地点、plotline 和状态信息，而不需要重新设计 v0.3 数据模型。

## 测试计划

- 大纲解析测试覆盖标题层级、空标题、重复标题、Beat、混合中英文、非法层级跳跃、fenced code block 和确定性输出。
- Structure Skeleton 测试覆盖 Manuscript 卷章、场景卡、规划草稿 outline draft 和失效场景的合并规则。
- 导入预览测试覆盖四种 scope、include 链路、复用已有卷/章、新建缺失父级、取消不写文件；确认后只通过 Manuscript actions 修改手稿结构。
- 场景卡校验测试覆盖 frontmatter 缺失/损坏、重复 `id`、非法 `chapterRefs`、非法 `order`、重复 order、坏人物/地点引用、未知字段保留和旧 `chapterId` 兼容读取。
- 幂等与恢复测试覆盖重复导入同一大纲不重复创建已有场景；部分失败不能留下 manifest 与场景卡互相矛盾。
- UI/命令测试覆盖 Outline Tree 节点分组、图标 context、右键菜单显示条件、跳转章节、跳转 Story Bible 条目和刷新。
- 垃圾桶测试覆盖删除、还原拒绝覆盖、永久删除危险确认和 trash metadata 损坏 diagnostics。
- Projection 测试覆盖按 Manuscript 卷章顺序输出、同章节场景 order 排序、多章节绑定重复投影、失效章节引用降级和 v0.4 所需字段完整性。

## 风险

- 场景卡字段过多。
- 大纲导入和手稿生成的关系如果在树上表达不清，会让用户误以为“规划草稿”是第二套结构。
- 在场景身份稳定前开始做 Plot Grid。
- 导入幂等如果只靠标题会误合并重复章节或重复场景。
- 过早引入 Webview 会把 v0.3 做成第二个 Plot Grid。
- Story Bible 引用既支持 Card ID 又支持 keyword slug，UI 必须显示清楚稳定身份，避免用户混淆显示名和持久化值。
