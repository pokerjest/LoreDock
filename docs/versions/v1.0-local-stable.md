# v1.0 Local Stable

## 目标

把 LoreDock 稳定成一个可靠的本地小说工作区。v1.0 是第一个面向长期严肃项目使用的版本。

v1.0 同时是兼容性分界线：在它之前，存储结构和代码架构可以为了找对方向而破坏式调整；从它开始，项目格式必须向后兼容，后续版本不能随意让旧项目失效。

## 实现

- 冻结核心 schema 合约：
  - project manifest
  - manuscript structure
  - story elements
  - outline documents
  - scene cards
  - reference index
  - timeline events
  - diagnostics
- 覆盖所有 v1 前 schema 的 migration。
- 定义正式兼容性政策：
  - v1.0 之后所有正式项目必须能被新版本打开。
  - schema 变化必须有 migration。
  - 删除公开字段、命令或文件结构前必须先 deprecated。
  - 重要迁移必须先快照或提供恢复路径。
- 复审完整命令列表。
- 完成 README。
- 增加示例项目。
- 完成 CHANGELOG。
- 建立 `.vsix` 打包流程。
- 建立集成测试套件。

## 优化

- 大型项目激活性能。
- 增量索引可靠性。
- 文件 watcher 行为。
- Plot Grid、Graph、Timeline 的内存占用。
- 损坏项目文件的错误恢复。

## 打磨

- 命令、视图、文件和文档命名统一。
- 中文 UI 文案复审。
- 更好的空状态和诊断提示。
- Starter project templates。
- 发布 checklist。

## 验收标准

- 用户不需要 AI 或网络，也能长期维护长篇小说。
- 核心能力组合使用不会造成数据损坏。
- 单个坏文件不会拖垮整个项目。
- v1.0 项目 fixture 能在后续版本测试中作为兼容性基线。
- migration 测试能证明旧正式项目可以升级到当前 schema。
- 测试端到端覆盖主要工作流。
- 插件可以打包并安装为 `.vsix`。

## 风险

- schema 冻结太早。
- 可选高级功能拖慢核心稳定。
- migration 测试不足就发布。
