# v0.6 World Modules

## 目标

通过模块扩展故事圣经，而不是把所有未来世界观类型都硬编码进核心。

## 实现

- 增加故事元素类型的 module schema registry。
- 新增内置类型：
  - faction
  - item
  - species
  - organization
  - event
  - magic-system 或 technology-system
- 每个项目可以启用或禁用模块。
- 每个模块有独立模板文件。
- 通用关系字段：
  - relatedCharacters
  - relatedLocations
  - relatedRules
  - relatedEvents
  - sourceRefs
- 可见性模型：
  - public
  - private
  - spoiler
  - hidden

## 优化

- module schema 要小而声明式。
- 避免每种故事元素都写一套自定义代码。
- 禁用模块时保留用户文件，只隐藏相关命令和视图入口。
- 搜索和索引必须支持模块类型。

## 打磨

- 项目初始化时提供模块选择器。
- 提供题材友好的模块预设。
- 对公开信息和隐藏信息给出清楚标签。
- 文档说明如何创建本地 module schema。

## 验收标准

- 新故事元素类型可以通过 schema 加入，而不改 Kernel 代码。
- 搜索、树视图和反链能用于 module-defined 类型。
- 禁用模块不会删除用户文件。
- 测试覆盖模块注册、模板创建、启用/禁用和索引。

## 风险

- 插件系统设计过宽，超过当前需要。
- module schema 变成不稳定的编程语言。
- 内置模块过多，导致 v0.6 变臃肿。
