# v1.3 Assistant Layer

## 目标

在本地结构稳定后加入可选 AI。助手应该帮助总结、润色和提出建议，但不能变成必需基础设施。

## 实现

- Assistant capability 默认关闭。
- 使用 OpenAI-compatible 配置。
- Provider profiles 只是预设，不绑定硬依赖。
- 上下文选择器：
  - 当前选区
  - 当前章节
  - 选中场景
  - 选中故事元素
  - 引用摘要
- 命令：
  - 总结章节
  - 润色选区，必须 diff 预览
  - 建议故事圣经更新
  - 建议一致性问题
  - 生成场景扩写草稿
- 待审建议队列写入 `.loredock/pending/`。
- 本地 assistant history。

## 优化

- 请求上下文必须有边界且可解释。
- 默认不上传整个项目。
- 摘要可以缓存，但允许重新生成。
- 所有生成编辑都必须可审查。

## 打磨

- 未配置 AI 时有清楚 disabled state。
- 提供模型测试命令。
- 文本变更使用 diff UI。
- 待审建议按目标文件分组。
- 文档说明隐私和本地优先行为。

## 验收标准

- 没有 AI 配置时，所有非 AI 功能正常工作。
- AI 不直接修改手稿正文。
- AI 不直接修改故事圣经文件。
- 建议可以接受、拒绝或忽略。
- 测试覆盖上下文组装、pending queue 和 diff 应用边界。

## 风险

- AI 反过来压迫数据模型设计。
- 上传过多上下文。
- 把建议事实和确认 canon 混在一起。
