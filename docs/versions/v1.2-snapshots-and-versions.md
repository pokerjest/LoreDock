# v1.2 Snapshots and Versions

## 目标

通过快照、对比和恢复工作流保护长篇写作过程。用户在导出、导入、修复和大型编辑前应该有安全感。

## 实现

- 增加 `.loredock/snapshots/`。
- 快照系统应挂接统一 operation apply 流程，在删除、移动、修复和导出前按需创建快照。
- 快照类型：
  - 项目快照
  - 章节快照
  - 故事圣经快照
  - 导出前快照
  - 修复前快照
- 快照元数据：
  - id
  - reason
  - createdAt
  - file list
  - checksum list
- 对比当前文件与快照。
- 恢复单个章节或故事元素。
- 快照清理策略。

## 优化

- 快照尽量紧凑存储。
- 尽可能避免重复保存大量未变化文件。
- 恢复操作保持目标明确且安全。
- 快照创建速度要足够支持 pre-operation 使用。

## 打磨

- 简单快照浏览器。
- 人可读的快照原因。
- 恢复前必须预览。
- 清楚提示快照不是云备份。

## 验收标准

- 导出和修复前会先创建快照。
- 用户可以对比并恢复单个文件。
- 恢复不会在未确认时覆盖文件。
- 测试覆盖快照创建、checksum、对比、恢复和清理。

## 风险

- 在 LoreDock 里重造完整版本控制系统。
- 鼓励危险的全项目回滚。
- 快照无限增长。
