# v1.4 Blueprint Studio

## 目标

为需要图形结构的用户加入高级视觉规划层。Blueprint Studio 可以强大，但必须可审计，并且要和手稿写作分离。

## 实现

- 增加 Blueprint capability。
- `.loredock/blueprints/` 保存机器 JSON。
- `.loredock/blueprints-md/` 保存可读 Markdown 导出。
- 节点类型：
  - chapter
  - scene
  - character
  - location
  - rule
  - event
  - plotline
  - note
- `chapter` 节点必须引用 v0.1 稳定 `chapterId`，标题和路径只作为显示 projection。
- 关系类型：
  - flow
  - uses
  - causes
  - foreshadows
  - resolves
  - conflicts
  - supports
  - blocks
- Markdown directives：
  - `@blueprint`
  - `@node`
  - `@port`
  - `@wire`
  - `@view`
- 导入/导出必须 preview first。
- 旧 `@edge` 只作为导入兼容；再次导出必须变成 `@wire`。

## 优化

- 画布状态和 canon 状态分离。
- 所有节点和 wire 使用稳定 ID。
- 禁止隐藏 HTML 注释、base64 或 opaque metadata。
- 同步必须冲突安全。

## 打磨

- 从大纲创建蓝图。
- 从当前章节创建蓝图。
- 从当前章节创建蓝图时通过 v0.1 `ManuscriptReader` 读取上下文，不能直接修改 `manuscript/`。
- 按节点类型和关系类型过滤。
- 视角书签。
- 清晰同步预览。

## 验收标准

- 蓝图 Markdown 人能读，插件也能还原。
- 导出保留 ID、标题、端口、wire、布局、颜色、标签、locked/collapsed、关系说明、strength、status 和 view bookmarks。
- Pull/Push 必须预览。
- 冲突默认 skip。
- 蓝图转换永远不能修改 `manuscript/`。

## 风险

- 图编辑变成产品中心，压过写作。
- 视觉布局被误当成 canon。
- 违反 plaintext blueprint 规则。
